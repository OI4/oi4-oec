# D7/D8 compliance tools – architecture (P3, C-044)

Status: **design sketch**, proposed with [ADR-0025](../../project/decisions/ADR-0025-compliance-tool-architecture.md).
Built so far: `oec-check validate` (P2), the test catalog (`catalog/`, C-044) and – since **C-052** – `internal/mqttwire`, `internal/capture`, `internal/verdict`, `internal/monitor` and `oec-check monitor` (live and `--replay`, 13 of the 19 monitor tests, 18 since C-065, 19 since C-067), and since **C-062** `oec-check test` (all 55 D7 tests `implemented` since C-068), since **C-069** `list`, `explain`, `report-schema`, the frozen `report.schema.json` and the catalog coverage report, since **C-070** the first D8 command `oec-infra image`, since **C-071** `oec-infra bus` (the "As built" notes below are amendment C-052 of ADR-0025 and its successors). Everything else is the plan for P5b (D8, ROADMAP P5b).
Inputs: ADR-0006 (independence, modes), ADR-0013/0014 (Go, one module, two binaries), ADR-0016 (levels), ADR-0019 §5 and amendment C-040 item 7 (`validate` contract), RIG (D8), Q-009.

## 1. Scope and principles

- **Two binaries, one module** `github.com/OI4/oec/conformance`: `oec-check` (D7, application/messaging) and `oec-infra` (D8, Service Container and platform). They may share `internal/` packages (report, catalog, MQTT wire code).
- **Independent of the SDKs** (Q-009, ADR-0006): the only shared inputs are the data modules `oec/spec` (requirements, topic grammar, matrix, vectors) and `oec/schema` (JSON Schemas). `catalog/independence_test.go` fails if `go.mod` references any other `oec/` module.
- **Black box**: the tools see only what crosses the wire (MQTT, TLS) or the container/host boundary (OCI image, Engine API, file system). Requirements that cannot be observed that way are `manual` in the catalog with a reason.
- **Every verdict names REQ ids.** A test exists only as a catalog entry (§6); the catalog covers every `d7-monitor`, `d7-test` and `d8` REQ, enforced by `catalog_test.go`.
- **Pure Go, no cgo**, static binaries for Windows/macOS/Linux × amd64/arm64 (ARMv7 best effort, Q-008).

## 3. D7 `oec-check`

### 3.1 Commands

| Command | Purpose | Network |
|---|---|---|
| `validate` | one message or a message file (exists; contract ADR-0019 amendment C-040 item 7) | none |
| `monitor` | passive observation of the bus; runs `validate` on every message plus the stateful rules (T7-MON-01 … 19) | subscriber |
| `test` | active test against one running CUT (T7-CON/LIFE/ADR/GET/SET/ACT) while the monitor rules keep running | client or proxy |
| `list` | catalog listing, filterable (`--mode`, `--level`, `--req`, `--needs`) | none |
| `explain <test or REQ id>` | test description, REQs with statements and source anchors | none |
| `report-schema` | prints `report.schema.json` (C-069) | none |
| `version` | tool, schema release, spec baseline, catalog versions | none |

### 3.2 `monitor`

```
oec-check monitor --broker mqtts://host:8883 [--ca … --cert … --key …] \
                  [--app <AppId>] [--level 1|2|3] [--duration 10m] \
                  [--record capture.jsonl] [--report json=r.json --report junit=r.xml]
oec-check monitor --replay capture.jsonl [--app <AppId>] [--level N]
```

- Subscribes to `Oi4v2/#` with **QoS 1**: the delivered QoS is then the publisher's QoS (min of both), so REQ-MQTT-xxx about publish QoS is observable; retain flags of delivered messages show retained publications.
- Per message: the `validate` layers (topic, parse, schema, rules R-2/3/4/6). Per CUT (keyed by ServiceType + AppId): stateful rules – Birth/Health timing, uniqueness of MessageIds/RequestIds/IL, DataSetWriterId/DataSetClassId consistency, PublicationList semantics (Mode, Interval, Precisions), pagination chains (R-5 multi-message rules).
- `--app` restricts verdicts to one CUT; without it every component seen is judged (useful for a whole Service Container). Messages of other components are still used as context (e.g. requests addressed to the CUT).
- `--record` writes the capture; `--replay` runs the same engine offline and deterministically (rule regression tests, bug reports, CI). The recording is a superset of the `validate` message file: `{"topic", "payload", "received", "qos", "retain"}` per line plus a header line with tool/schema/baseline version.
- Time-based rules (e.g. Health every 60 s, PublicationList Interval) need a minimum duration; if `--duration` is too short the affected tests end as `skip` with the reason "observation too short".

**As built (C-052, ADR-0025 amendment C-052):**

- Flags: `--replay FILE` or a live connection (§8); `--record FILE`, `--duration` (default 5 min > the 2 × 60 s + 5 s the heartbeat needs), `--app`, `--level` (default 3, REQ-CMP-011), `--allow-skip`, `--heartbeat` (60 s), `--tolerance` (5 s), `--max-packet-size`, `--format text|json|junit`, `--report FORMAT=PATH`, `--config FILE.yaml`. Live-only flags are usage errors with `--replay`. A live run stops at the end of `--duration`, on SIGINT/SIGTERM or when the connection is lost (the reason is in the report and the capture trailer); the verdicts of the observed part still count.
- **Capture format v1** (`internal/capture`): line 1 is the header `{"format": "oec-capture", "version": 1, "tool", "tool_version", "schemas", "baseline", "broker", "insecure", "subscription", "subscribe_qos", "max_packet_size", "started", "note"}`; then one record per message `{"topic", "payload" | "payload_base64", "size", "received", "qos", "retain"}` (`payload` = the JSON as received, compacted; a payload that is not JSON is kept in `payload_base64`; `size` = bytes as received); an optional last line is the trailer `{"ended", "messages", "error"}`. Records are in reception order with non-decreasing `received`; the reader is strict (unknown keys fail). `validate` accepts a capture as a message file. Replay takes `subscribe_qos` and (unless `--max-packet-size` is set) `max_packet_size` from the header; the observation ends at the trailer (else at the last record).
- **Participants** are keyed by the PublisherId (`<ServiceType>/<AppId>`) and summarized in the report (messages, invalid, Births, Wills, Closes, Sources, first/last). `--app` accepts the AppId or the PublisherId; the other components are still observed as context, but only the CUT's verdicts count. A CUT that is never seen makes every implemented test `skip` (inconclusive, exit 4).
- **Implemented** (catalog status `implemented`): T7-MON-01 … 08, 10, 11, 12, 18, 19. **Deferred** (`planned`): T7-MON-09 (DataSetClassId per structure across reconnects), 13 (Data/Event publications), 14 and 15 (PublicationList Mode/Interval/Precisions and republication), 16 (RevisionCounter), 17 (Set Config objects) – they need the PublicationList/Config state model of `test`.
- Rule decisions: a Will is recognized as a Health/MAM message of the component whose MessageId timestamp is not newer than the component's last Birth (REQ-LIFE-016: the Will is registered at CONNECT, before the Birth); the heartbeat (REQ-TOP-017) is judged for the Health of the component itself (`Source` = `AppId`, SF-106) and restarted by any own Health or Birth; REQ-RES-HEALTH-004 (a change of a DetailObject) is not observable and ends as a not-applicable `skip`; IL uniqueness (T7-MON-10) is a heuristic (`info`); while connected, an unsolicited Pub MAM about itself with another RevisionCounter than the current MAM is the MAM published on change (REQ-RES-MAM-018), not a second Birth, and later MAMs about itself are compared with it (C-056).

### 3.3 `test`

```
oec-check test --broker … --app <AppId> [--level 3] [--attach bus|proxy] \
               [--listen :8883 --server-cert … --server-key …] \
               [--restart-cmd "docker restart cut"] [--peer] [--tests T7-GET-*] \
               [--announce] [--report …]
```

- `--level` default **3** (REQ-CMP-011: a component labeled compliant without a stated level fulfills level 3). Tests whose `level` is above the declared level are not run; each REQ of a run test is judged by its own obligation at the declared level (§5).
- Discovery: the CUT's MAM/Health/Profile (retained or by `Get`) decide applicability: which resources, subordinate assets, Config groups, PublicationList entries exist.
- Stimuli: `Get` (with paging, query, locale, unknown keys), `Set`/`Del` on every modifiable resource (with restore of the original content where possible), `Call NewDataSetWriterId`, malformed and unaddressable requests (T7-ACT-03). Responses are correlated by CorrelationId/RequestId with a timeout (`--timeout`, default 10 s).
- **Side effects**: `test` changes the CUT's configuration. The tool restores the content it changed and lists every change it could not restore in the report. It refuses to run without `--app` (never against "all").
- The monitor engine runs during `test`; its findings are part of the same report.

**As built (C-062, ADR-0025 amendment C-062):**

- `oec-check test --app [<ServiceType>/]<AppId> (--broker … | --bus-storage …) [--level N] [--timeout 10s] [--tests ID|GLOB,…] [--tester-il IL] [--record FILE] [--format …] [--report …] [--config FILE.yaml]`; the connection, verdict and output flags are those of `monitor` (§3.2, §8); `--replay` and `--duration` do not exist for `test`. Only the bus attachment; `--attach`, `--listen`, `--restart-cmd`, `--peer` and `--announce` come with the increments 5 and 6 of the P5 plan. The AppId is given as Identification Link, i.e. with the dnp-encoded Oi4Identifier elements (`OEC,20Demo`).
- One subscription `Oi4v2/#` (QoS 1): every message goes to the monitor engine (and the recording), then to the runner `internal/probe`. A recorded test run replays with `monitor --replay`.
- Discovery: `Get MAM/<AppId>` on the given ServiceType or on all seven; the first answer fixes the ServiceType; fallback: a publication of the AppId seen during discovery; not found → every REQ inconclusive (exit 4). The CUT is treated as an application. Responses to `Get` are correlated by `ReplyTo` = MessageId of the request. Requests are published with QoS 0 (REQ-MQTT-017 default) by the not-announced tester `Utility/oi4.org/oec-check/D7/<12 hex>` (§3.5).
- Tests run sequentially in catalog order. A request that expects an answer waits until answered plus 250 ms (duplicates), one that expects no answer waits `--timeout`. Each active test judges only the REQs its catalog entry cites.
- Implemented: T7-GET-01 (Get MAM and Health, with and without Source, for the application and up to 20 subordinate Sources), T7-GET-02 (every resource of the Profile of the application answers, the Profile lists the resources of the level), T7-GET-05 (Get without content → empty list; unknown Source → no Pub, Event Status Bad `BadNotFound`; REQ-CMP-044 is a MAY and not stimulated), T7-GET-09 (Get MAM with an unknown key answered like without it).
- Verdict of a test run: passive REQs that the short run cannot judge (connect not observed, shorter than the heartbeat, MaxPacketSize unknown) are plain skips with the reason prefix "test run:", not inconclusive; a level claim needs a `monitor` run ≥ the minimum duration in addition (§6). Non-selected tests are skip "not selected (--tests)".
- Report: the monitor report (version 1) with `"mode": "test"`, `tester` and `requests` (test, topic, MessageId, sent, replies).

**As built (C-063, ADR-0025 amendment C-063):**

- T7-GET-03: every resource of the Profile answers Get without Source, with the Source of the application and with up to 5 Filters taken from the first answer (the Filter answer is a subset with that Filter); every PublicationList entry (up to 50) of a requestable resource with a Mode other than `OFF_0` answers Get; Get Metadata is requested only for the Data announced in the PublicationList (REQ-CMP-044 is a MAY).
- T7-GET-04: the application and every subordinate Source (up to 20) answer Get with their Source for every resource of the level; at level 2 the recommended resources are REQ-CMP-010.
- T7-GET-06: Get MAM without PaginationRequest is the complete series; with `PerPage` 1 the pages 1, one beyond the end and 0 (all pages) are judged (REQ-PAG-002/005). Pagination by size cannot be stimulated; T7-MON-18 judges `MaxPacketSize` passively.
- T7-GET-07: Query `Parent` of ReferenceDesignation (the first parent with fewer children than objects), the same with an undefined parameter, a Query on Get ReferenceDesignation/<AppId> (judged against the same Get without Query) and a Query on Get MAM (ignored). Without any ReferenceDesignation object the answer to a Query is not judged.
- T7-GET-08: Get MAM and Get Config/<AppId> with the Locale `de-DE`; every LocalizedText of the answer is `de-DE`, `en-US` or invariant.
- T7-ADR-02: watches `Oi4/#` best effort; a message under `Oi4` with the MessageId of a request of D7 fails REQ-TOP-004; without `Oi4` traffic the REQ is skipped.
- T7-ADR-03: Get MAM with the exact IL of each asset answers exactly that IL; a case variant is not answered as the same asset.
- Monitor engine during `test`: an answer to a Get with a Locale is not compared with the Birth (REQ-LIFE-003), an answer to a Get for one page (`Page` > 0) is a complete series of its own (REQ-PAG-005).

**As built (C-064, ADR-0025 amendment C-064):**

- Write tests T7-SET-01 … 09, 11, 12 (`internal/probe/set.go`); T7-SET-10 (restart) follows with increment 6 (C-067). They run after the `Get` tests; T7-SET-03 (level 3, REQ-CMP-033) runs last and reuses the reactions of the others, stimulating only the missing Set/Del combinations (supported = any reaction with the `ReplyTo` except BadNotSupported).
- State model: before the first write test D7 reads the Profile, the assets and the state (Get without Source of Config, PublicationList, ReferenceDesignation, SubscriptionList); after the last one it reads the state again and compares (`probe.Restore`: `checked`, `restored`, `changed`, `note`). Data is not compared (its values change by themselves), the disk of the CUT is not compared.
- Every write is a write-back or a change that is undone: a Set sends what the CUT published (Config as the full DataSet including the mask of sensitive values, Data only where a Set subscription is listed); entries with Config `NONE_0` get only a change that must be rejected; changed Modes are set back; only SubscriptionList entries D7 created are deleted; a ReferenceDesignation is deleted only with a known state and after a write-back Set of it got Status Good, and restored with Set (else the Del is skipped); a Config DataSet with a masked sensitive value is written only where REQ-RES-CONFIG-025 is MUST (level 2, 3). Unknown objects carry the prefix `d7`/`D7`.
- Reaction: the Event of the category Status with the MessageId as `ReplyTo` (level from the severity bits; Source = Source of the request, the AppId for an unknown asset, SF-108) and, after a successful Set, the publication with the same `ReplyTo` on the Pub topic of the object. "Nothing published" (REQ-BUS-007) is judged until the Status event plus the grace time.
- Per test: SET-01 Set of every offered object (Status event, publication, REQ-RES-SUBLIST-016 after the catalog note); SET-02 unknown object/asset → Status Bad; SET-04 Del of a whole object and of a part; SET-05 Config write-back, unknown object, changed read-only Name, invalid Number (deliberate, tester violation REQ-RES-CONFIG-007); SET-06 Data; SET-07 Metadata; SET-08 PublicationList write-back, `NONE_0` Mode change, Data `OFF_0` hides the Data; SET-09 ReferenceDesignation Set/Del/Set; SET-11 SubscriptionList write-back, `NONE_0` change, creation (optional, SF-111) and Del; SET-12 a Syslog level switched and set back.
- Report: key `restore` (omitted without write tests; report version 1 unchanged), a "restore:" line in the text report; `oec-check test` warns on stderr with the changed lines if the state was not restored. A run that ends during the write tests reports `restore` as not checked with a note naming the test (and warns); with masked sensitive values the note says that they cannot be compared. The restore result is not a verdict.

**As built (C-065, ADR-0025 amendment C-065):**

- Action tests T7-ACT-01 … 04 (`internal/probe/action.go`), run inside the write window after the write tests: D7 calls `NewDataSetWriterId` (DataSetWriterId 8, ActionTargetId 1, `{"Resource": "Data"}`) on `Call/NewDataSetWriterId[/<Source>]` with ResponseAddress = the matching `Reply` topic (REQ-TOP-016) and `RequestorId` = the tester; responses are correlated by `RequestorId` and `RequestId` (any Reply topic of the CUT, so a wrong topic is a finding, not a timeout). A provided id is only reserved by the CUT, D7 never uses it, so the restore check compares the same state.
  - ACT-01: one request without Source and with CorrelationData, one with the AppId as Source and without; per answered request MessageType, topic, CorrelationData echoed (or absent), DataSetWriterId/ActionTargetId of the request, CompactEncoding Status without Symbol, ActionState 1 (any number, MAY) or 2 (exactly one final), Payload object; a Good final response provides an id ≥ 10 that the CUT neither publishes nor lists in its PublicationList and that is new, with a UInt32 Ttl. No answer: a violation of REQ-CMP-034/040 where they apply, of the ACT REQs if the CUT offers the service (Profile) or REQ-CMP-040 is MUST at the level, else a skip.
  - ACT-02: two more requests while the earlier ids are reserved get ids not provided within their Ttl; the initial use within the Ttl needs a create, which D7 does not do (manual part, catalog note).
  - ACT-03: an unknown DataSetWriterId (4), an unknown ActionTargetId (2) and an undecodable request get no response within `--timeout`; a valid request beside them shows that the CUT answers at all (else skip). The two schema-invalid requests are deliberate tester violations (REQ-ACT-019).
  - ACT-04: a request for an unknown Source is answered with `{"Code": 2151546880}` (BadNotFound, 0x803E0000) and an empty Payload.
- Report: `requests` lists the `NewDataSetWriterId` calls with the Get/Set/Del requests, ordered by the time sent; `replies` of a call counts its ActionResponses (by `RequestId`). The deliberately unanswerable calls of ACT-03 therefore appear as unanswered.
- Monitor rules T7-MON-09, 13, 15, 16, 17 (`internal/monitor/config.go`); the state per participant survives reconnects. T7-MON-14 (PublicationList Mode/Interval/Precisions) followed in C-067.
  - MON-09: the structure of a DataSet is its sorted field names (Metadata `Fields[].Name`, Data payload keys) per DataSetWriterName and WriterGroupName; a DataSetClassId with another structure, or the same DataSet with the same structure under another DataSetClassId, is a violation of REQ-MSG-013.
  - MON-13: for a component with Sources, Data and Event are supported if published or listed in its own Profile; a Profile without them and no publication is a violation (REQ-CMP-010/036/038); without Profile and publication the rule skips (not a gap: `test` requests the Profile).
  - MON-15: after a Set (or Del) of the PublicationList/SubscriptionList answered with Status Good the list is published again – with an empty `ReplyTo` or the MessageId of the Set (MAY REQ-RES-PUBLIST-018/SUBLIST-006 checked on the latter) – within the tolerance; after a Del SubscriptionList the absence is a plain skip (REQ-RES-SUBLIST-015, remaining entries are not observable).
  - MON-16: the RevisionCounter of an asset never decreases and never changes between -1 and a counter; after a Set Config answered with Status Good that changes a known, non-sensitive Value, a MAM of that Source later than the tolerance must carry a larger counter (the exact +1 is not judged: other changes may count too). Without a later MAM the rule skips (inconclusive in `monitor`).
  - MON-17: a Set Config contains, for every group it contains, each object the addressed component published with `Mandatory` = true, with a Value (REQ-RES-CONFIG-011); the flags come from the Pub Configs of the same Source and WriterGroupName, merged per object. Without a Pub Config before the Set the rule skips for the sender. In `test` only the CUT's own Sets are judged (the tester's are filtered out with the other participants).

**As built (C-066, ADR-0025 amendment C-066):**

- Connection and lifecycle tests T7-CON-01 … 04 and T7-LIFE-01 … 03 (`internal/probe/lifecycle.go`) judge what the proxy (§3.4) saw. Order of a run with the proxy: D7 subscribes, serves the proxy and waits up to `--proxy-wait` (default 2 min) for a relayed connection of the CUT with a PUBLISH and the broker's first SUBACK (so the discovery Get does not overtake the CUT's subscriptions, which a conforming CUT may send after its Birth), bounded by CONNECT + `--timeout`; then the other tests; then the connection phase: the next three attempts get TLS 1.1 only, an untrusted CA and a wrong host name, the relayed connection is dropped without DISCONNECT, and D7 waits for the reconnection with a Birth (or `--timeout` after its CONNECT) and the Will on the bus (or `--timeout` after the drop); then every connection of the run is judged.
  - CON-01: protocol level ≥ 4 (REQ-MQTT-001/CMP-001); ClientId not empty and the same on every connection (REQ-CMP-009); keep alive ≠ 60 s and clean session false are notes (configurable values are allowed, MG 6.2.3).
  - CON-02: every relayed connection uses TLS ≥ 1.2 (REQ-MQTT-005); a CONNECT in a reject phase is a violation (TLS 1.1: REQ-MQTT-005/CMP-002; CA, host name: REQ-MQTT-008/CMP-002); a phase not reached because the CUT did not reconnect within `--proxy-wait` is an inconclusive skip.
  - CON-03: client certificate or user name and password (REQ-MQTT-009). CON-04: no Will Retain and no PUBLISH with Retain (REQ-MQTT-018).
  - LIFE-01: every CONNECT carries the Will on `Pub/Health/<AppId>` without Retain (REQ-LIFE-008, REQ-CMP-003), without Timestamp and SequenceNumber (REQ-LIFE-010), created anew for the connection: the time of its MessageId within `--tolerance` of the CONNECT and no repeated MessageId (REQ-LIFE-016).
  - LIFE-02: a Birth (Pub MAM of the CUT about itself without `ReplyTo`) on every relayed connection within `--timeout` (REQ-LIFE-001), as the first PUBLISH (REQ-LIFE-015); after a self Health `FAILURE_1`/0 the next other Health follows a new Birth (REQ-LIFE-017; skip without such a failure); no reconnection after the drop is an inconclusive skip.
  - LIFE-03: the Will is the Health of the CUT about itself with `FAILURE_1`/0 and the DataSetWriterId of its own Health (REQ-LIFE-009); the broker's publication of the Will is recorded on the bus.
- Without the proxy every CON/LIFE requirement is an inconclusive skip ("needs proxy") – exit 4 unless `--allow-skip`; a retained delivery of the CUT on D7's subscription is still a T7-CON-04 finding.
- Monitor (both modes): T7-MON-03 reports a missing Birth after a Will only when the connection or the observation ends without one (a late Birth is REQ-LIFE-015, T7-LIFE-02); T7-MON-10 does not count the Birth after a recovery or a late Birth as a second Birth.

**As built (C-067, ADR-0025 amendment C-067):**

- Restart tests T7-LIFE-04 and T7-SET-10 (`internal/probe/restart.go`) with the restart hook (§3.4): flags `--restart-cmd CMD` or `--stop-cmd CMD --start-cmd CMD` (run one after the other by `sh -c`, Windows `cmd /C`; output to stderr, a background start must redirect its output) and `--restart-wait` (default 2 min). The restart phase runs in the write window after the other write tests and before the restore check, so T7-SET-10 restores its change and the restore check covers the restart: (1) SET-10 sets a changed ReferenceDesignation (the object of the application, else the first one; "D7" appended to Value and Local of its first aspect) and needs Status Good; (2) the hook; (3) D7 waits up to `--restart-wait` for the new Birth (through the proxy: a new relayed connection with Birth and first SUBACK) and an answer to Get Health (one retry for a CUT that subscribes late); (4) LIFE-04 and the SET-10 read-back and restore.
  - LIFE-04: the Close message is the last Pub Health of the CUT (not an answer) after the start of the hook and before its DISCONNECT (proxy) or before its new Birth (bus). Judged: present (REQ-LIFE-005), on `Pub/Health/<AppId>` (REQ-LIFE-006), one Health DataSetMessage `NORMAL_0`/0 with the DataSetWriterId of the CUT's Health from Get Health after the restart (REQ-LIFE-007), graded by REQ-CMP-046. PUBLISH packets after the Close message before the DISCONNECT are a note. Inconclusive skip: no hook, the connection did not end, it ended without DISCONNECT (proxy), the Will on the bus, or no new Birth within `--restart-wait` (bus).
  - SET-10: after the restart Get ReferenceDesignation returns exactly the changed object (REQ-RES-REFDES-002); not applicable (plain skip) without a ReferenceDesignation object or with Status Bad on the Set (the condition "offers Set ReferenceDesignation" is not met).
- Monitor rule T7-MON-14 (`internal/monitor/publist.go`, both modes): the rules are the entries {Resource, Source, Filter} of the last observed Pub PublicationList of a component (unsolicited or a Get answer; an absent Mode is `ON_REQUEST_1`). Topic forms are a bit set (application `Pub/<Res>`, source `…/<Src>`, filter `…/<Src>/<Filter>`; resources without Filter count the source form as both); an unsolicited publication is mapped to its entry by Resource and Source, then the topic Filter, then the DataSetWriterId (unique match only).
  - Not judged (recorded only): the Birth, the Will and the Close message; publications while the rules are uncertain (after a Set/Del PublicationList addressed to the component until its next Pub PublicationList) or the component is offline; publications within the tolerance after an entry changed or after a connect; `OFF_0` (T7-SET-08); Event intervals; Get answers with a Locale.
  - Mode: an unsolicited publication of an `ON_REQUEST_1` entry (not MAM/Health) violates REQ-RES-PUBLIST-008; a form the Mode does not enable violates the REQ of each enabled form (009/010/011, "enables" = the publication uses an enabled form); a used enabled form is checked.
  - Interval > 0 (not Event): a gap per form longer than Interval + tolerance violates 013 (and 014 if the entry has Precisions); the end gap counts while connected and certain.
  - Interval 0 with Precisions: a change of a listed field only below its Precision violates 015 (SHOULD); a change above is checked.
  - Interval 0: a Get answer (publishing Mode, not localized, not Event) that differs significantly from the last unsolicited content expects an unsolicited publication of it within the tolerance; without it 013 and REQ-MQTT-019 are violated.
  - A component that publishes but whose PublicationList was never observed skips all 8 REQs inconclusive (`test` requests it with Get PublicationList).

**As built (C-068, ADR-0025 amendment C-068):**

- Flags `--peer` (§3.4) and `--announce` (§3.5); report key `announced` (per component: `role` tester/peer, `publisher_id`, `requests` received, `answered`) and a text line per component.
- T7-ADR-01 (`internal/probe/adr.go`, `needs: [peer]`): a request of the CUT to the peer is a Get/Set/Del/Call with the CUT as PublisherId whose topic carries the peer's AppId or the peer as Source. Each is checked against the request topic of the peer `Oi4v2/Utility/<peer>/<Method>/…`: ServiceType (REQ-TOP-006), AppId (REQ-TOP-010), both (REQ-BUS-002; the detail names the expected topic); one violation per distinct topic. In its slot the test waits up to `--timeout` for a first request and judges at the end of the run (requests after the restart count). Without `--peer` an inconclusive skip (exit 4 without `--allow-skip`), with the peer but without a request a plain skip (the REQs apply to a requester). Requests of the CUT to the announced tester are only counted. A request with a wrong AppId and without the peer as Source cannot be attributed.

### 3.4 Attachment modes (`needs` in the catalog)

| Mode | How | What it adds | Catalog `needs` |
|---|---|---|---|
| bus (default) | D7 is an ordinary client of the broker (credentials with read on `Oi4v2/#`, write on the CUT's Get/Set/Del/Call topics) | everything visible to a subscriber/requester | – |
| **proxy** | D7 is the CUT's MQTT endpoint (TLS listener, `--proxy-listen`) and relays to the real broker; the CUT is configured to connect to D7 (Message Bus storage `broker.json` pointing to D7) | CONNECT details (protocol level, Will, clean session, keep alive, ClientId, credentials), TLS version/cipher offered by the CUT, certificate verification (D7 offers an untrusted CA / wrong host name / TLS 1.1 and expects the CUT to refuse), connection drops to provoke Will and recovery | `proxy` |
| restart hook | `--restart-cmd` / `--stop-cmd` + `--start-cmd`: graceful stop and start | Close message on graceful disconnect, persistence across restarts | `restart-hook` |
| peer | D7 simulates a second OEC component (own MAM/Health) that the CUT is expected to address | requests sent by the CUT | `peer` |

A test whose `needs` are not available ends as `skip` ("needs proxy"). For a level claim this makes the result **inconclusive** (§5.3). Proxy mode is the only way to check REQ-MQTT/REQ-SEC connection requirements of the CUT without broker log access ([Q-028](../../project/OPEN-QUESTIONS.md)).

**As built (C-066, ADR-0025 amendment C-066), proxy:** `internal/proxy`, an own minimal MQTT 3.1.1 relay on the Go standard library (paho has no server side). It decodes strictly only what it judges – the CONNECT (protocol name and level, flags, ClientId, keep alive, Will, user name, password presence) and the PUBLISH packets of the client (topic, QoS, Retain, payload, time) – and relays every frame unchanged in both directions; downward it notes the CONNACK code and the first SUBACK. TLS certificates for the proxy are issued at start from `--proxy-ca`/`--proxy-ca-key` (a CA the CUT trusts, ECDSA P-256 leaves): the relay certificate for `--proxy-name` (default `localhost`, `127.0.0.1`, `::1`), a wrong-host certificate for `wrong-host.invalid`, and a certificate of a fresh untrusted CA. Phases per attempt: `relay` (TLS ≥ 1.2), `tls1.1`, `untrusted-ca`, `wrong-host`; `Drop` closes the relayed connections without DISCONNECT. Upstream the proxy connects to `--broker` with D7's TLS settings and forwards the CUT's CONNECT (its credentials); a client certificate of the CUT is seen, not relayed. The report lists every attempt (`connections`, without payloads and password).

**As built (C-067, ADR-0025 amendment C-067), restart hook:** `--restart-cmd`, or `--stop-cmd` followed by `--start-cmd`, plus `--restart-wait`; a tester-provided command (systemd, `docker stop`/`start`, a script). D7 does not know how the CUT is deployed; a hook that kills the CUT instead of stopping it shows up as a stop without DISCONNECT (Will), which makes T7-LIFE-04 inconclusive. Through the proxy the connection before the hook is the one judged; on the bus only the publications the subscriber sees between the hook and the new Birth.

**As built (C-068, ADR-0025 amendment C-068), peer:** `--peer` (`internal/probe/peer.go`): a Level-1 `Utility` with the IL `oi4.org/oec-check/Peer/<12 hex>` (new per run) on its own MQTT connection (ClientId `oec-check-peer-…`). Lifecycle like a component: Will Health `FAILURE_1`/0 in its CONNECT; Birth (Pub MAM, Pub Health `NORMAL_0`/100) after D7's subscriptions and before D7 waits for the CUT; once the CUT is discovered a "present" Health, so a CUT that started later (always through the proxy) finds it; heartbeat every 30 s; at the end the Close message (`NORMAL_0`/0) and DISCONNECT. It answers Get MAM, Health and Profile without Source or with its own IL (with `ReplyTo` correlation), an unknown Source with Event Status Bad `BadNotFound` and no Pub (REQ-CMP-047), a Filter with an empty list; other resources are ignored. A lost peer connection ends the run with an error. The MAM elements are those of the IL (DeviceClass `Oi4.Utility`).

### 3.5 Tester identity

D7 needs an Oi4Identifier for its own requests (Source of Get/Set). Default: a tester IL generated per run (valid against the IL grammar, configurable with `--tester-il`) **without** publishing MAM/Health, so it does not appear as a component in the Registry. `--announce` makes D7 publish MAM/Health/Birth like a component (needed in `peer` mode and when a CUT only answers known components). Open: [Q-029](../../project/OPEN-QUESTIONS.md).

**As built (C-068, ADR-0025 amendment C-068):** Q-029 (a) – unannounced by default. `--announce` gives the tester the lifecycle and answers of the peer (§3.4) under the tester IL on D7's main connection (its Will is set in D7's CONNECT); `--tester-il` must then be an Oi4Identifier (4 elements), the MAM takes them. `--peer` does not need `--announce`: the peer is a component of its own.

## 4. MQTT layer

- Client and proxy share one codec: `github.com/eclipse/paho.mqtt.golang` v1.5.x (EPL-2.0 **or** EDL-1.0; taken under **EDL-1.0**, BSD-3-Clause, ADR-0023 rule on dual licenses) – the client for bus mode, its public `packets` package for the proxy endpoint and for raw stimuli (e.g. a PUBLISH with retain or an invalid UTF-8 topic that a normal client refuses).
- `eclipse/paho.golang` is MQTT 5 only → not usable (OEC uses MQTT 3.1.1).
- Broker for tests: the dev-env Mosquitto (P4 integration) or `mochi-mqtt/server` (MIT) embedded **in tests only**; decided in P5 by a spike, not part of the binaries. **As built (C-052):** neither spike nor mochi – `internal/mqttwire/mqtttest` is a small in-process TLS broker on the same paho `packets` codec (CONNECT with credentials or client certificate, SUBSCRIBE, PUBLISH QoS 0/1, Will on a lost connection; no retained messages, no QoS 2), so the gate needs no new dependency and no network beyond loopback. The dev-env Mosquitto is used by the opt-in `live.sh`.
- **As built (C-052), client:** `paho.mqtt.golang` **v1.5.1** (pinned in `go.mod`/`go.sum`, indirect `golang.org/x/net`, `golang.org/x/sync`, `gorilla/websocket` – BSD); `mqtts://` (also `ssl://`, `tls://`) only, TLS 1.2/1.3, CA from a PEM file (else system roots), credentials and/or a client certificate whose key may be an **encrypted PKCS#8** (PBES2: PBKDF2 with HMAC-SHA1/-256/-384/-512, AES-128/192/256-CBC – the format of the dev PKI and the RIG secret storage; other encryptions are refused with a clear error); clean session, no auto-reconnect (a lost connection is reported, not hidden), keep alive 60 s; `Kill()` drops the connection without DISCONNECT so that the broker publishes the Will (tests). `--insecure` skips only the broker certificate verification, prints a warning on stderr and is recorded in the capture header and the report.
- `--max-packet-size` (default: `MaxPacketSize` of the Message Bus storage, else the RIG minimum 262144 bytes) for pagination checks (REQ-PAG-xxx, MaxPacketSize).

## 5. Verdict model

### 5.1 Outcomes

| Outcome | Meaning |
|---|---|
| `pass` | all checked REQs of the test fulfilled |
| `fail` | a REQ whose obligation at the declared level is MUST/MUST NOT is violated |
| `warn` | a SHOULD/SHOULD NOT REQ is not followed (also: `validate` warnings) |
| `info` | a MAY observation, or a check that only gives hints (heuristics) |
| `skip` | not run: level above the declared level, not applicable (resource not supported), missing `needs`, observation too short – always with a reason |
| `manual` | listed for completeness: REQs of the catalog's `manual:` list and REQs with verification `manual` that the report should mention |

### 5.2 Severity

The severity comes from the REQ, not from the test: `levels.L<n>` of the REQ at the declared level (MUST → fail, SHOULD → warn, MAY → info, none → not judged). Ungraded REQs (no `levels`, e.g. platform REQs of D8) use their `keyword`. A test with several REQs reports one result per REQ; the test outcome is the worst of them. **As built (C-052):** a REQ that is `skip` because nothing applicable was observed (e.g. no Call sent, so no RequestId to check) does not make the test worse than `pass` ("all checked REQs"); a test is `skip` only if all its REQs are, and an *inconclusive* skip (a MUST that could not be judged: observation too short, CUT not seen) keeps the test `skip` and leads to exit 4.

### 5.3 Exit codes

| Code | Meaning |
|---|---|
| 0 | all run tests pass (warnings allowed) and no required test was skipped |
| 1 | at least one `fail` (the same as a `validate` violation) |
| 2 | usage error (flags, unreadable config) |
| 3 | internal error (tool bug, broker unreachable before any verdict) |
| **4** | **inconclusive**: no `fail`, but at least one test with a MUST REQ at the declared level was skipped (missing `needs`, CUT not found, observation too short) |

`validate` keeps 0–3 (it never skips). `--allow-skip` turns 4 into 0 for CI pipelines that run, e.g., only bus mode. Code 4 is new: [Q-030](../../project/OPEN-QUESTIONS.md).

## 6. Test catalog (`catalog/`)

- `d7.yaml` and `d8.yaml`, embedded with `go:embed`, loaded strictly (unknown keys fail). ## 11. Distribution

- `CGO_ENABLED=0` cross builds: windows/darwin/linux × amd64/arm64; linux/arm/v7 best effort (Q-008).
- Multi-arch container image `FROM scratch` (+ CA certificates) for CI use; `oec-infra container/host` need the Docker socket mounted and are documented as host-binary first.
- Release tooling (GoReleaser, MIT, or plain `go build` + scripts), signing and SBOM of the tools themselves decided in P9 together with Q-011 (CRA).
- Versioning: the tools carry their own SemVer; each report and `version` names the schema release and the spec baseline they embed.
