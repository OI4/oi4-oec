# Guardrails – OI4 OEC v2.0

These rules apply to every human and agent working on this project. A deviation requires an accepted ADR or explicit approval of the product owner, recorded in the cycle log.

---

## G-1 Sources and authority

| ID | Rule |
|----|------|
| G-1.1 | **Source of truth** (ADR-0001) are the two v2.0 guideline documents in `oi4-oec-documentation`: the **OEC Messaging Guideline** (`docs/guideline/`, cited as "MG x.y") and the **OEC Runtime & Infrastructure Guideline** (`docs/infrastructure-guideline/`, cited as "RIG x.y"). The guideline ADRs in `oi4-oec-documentation/rfcs_adrs/` (ADR-001 … ADR-016, cited as "GL-ADR-0xx" to distinguish them from our project ADRs) explain the rationale and their *Implementation Notes* are binding interpretations. The **OEC Process Description** (`docs/process-description/`, GL-ADR-015) is **informative** – no requirements are derived from it. The Confluence export under `oi4-oec-documentation/guideline/` and the PDFs (v1.1.0) are **historical reference only**. |

Always record the guideline revision (git commit of `oi4-oec-documentation`) you worked against in the cycle log. Current baseline: `b942df3` on branch `feature/spec-findings` (2026-10-22, GL-ADR-001 … 022, spec findings SF-001 … 090, 092, 093 resolved; SF-091 decided (accepted 2026-10-22, not yet implemented in the guideline; (d) resolved with GL-ADR-022); SF-094/095 (editorial, found in C-031) open, register `5ef2cc1`; next SF-096). ## G-2 Protocol invariants (derived from the guideline – must hold in every artifact)

Section numbers refer to the Messaging Guideline (MG) or the Runtime & Infrastructure Guideline (RIG). If the guideline changes, update this list in the same cycle.

| ID | Invariant | Guideline |
|----|-----------|-----------|
| G-2.1 | Topic schema: `Oi4v2/<ServiceType>/<AppId>/<Method>/<Resource>[/<Source>[/<Filter>]]`. Namespace is exactly **`Oi4v2`** for this version; `Oi4` denotes v1. A request is always answered in the namespace in which it was received; versions are never mixed. All deliverables are **v2 only**; v1 traffic is ignored (ADR-0015). `<Resource>` is a **closed set**: the 10 resources of MG 7.5.1 and the common service `NewDataSetWriterId` – any other resource/service name below `Oi4v2` is non-conformant (D7 reports it, the SDKs do not offer it; SF-036). | MG 7, 7.1, 7.5, GL-ADR-003, GL-ADR-014, SF-036 |
| G-2.2 | `AppId` and `Source` are the **base64url (RFC 4648 §5) encoded Identification Link, without padding**, forming exactly **one** topic level (max. 340 chars). There is exactly one valid encoding per IL. | MG 4.2, 7.3, 7.6 |
| G-2.3 | In payloads (`PublisherId`, `MessageId`, `ReplyTo`, `DataSetWriterName`, `RequestorId`, `ProductInstanceUri`, ...) the Identification Link is **always unencoded** and used exactly as assigned (no normalization, case-sensitive, char-by-char comparison). | MG 4.1, 4.2 |
| G-2.4 | Identification Link: ASCII subset of IEC 61406-1, max. 255 chars, lowercase authority, optional scheme (`https` recommended; with/without scheme = different ILs), no `%`. The `Oi4Identifier` (`ManufacturerUri/Model/ProductCode/SerialNumber`) is one optional way to build an IL; all IL rules apply to it, and its elements may be dnp-encoded (MG A3) to mask non-permitted characters or `/`. The dnp-encoding is used nowhere else. | MG 4.1, 4.3, A3 |
| G-2.5 | ServiceTypes (closed set): `Registry`, `OTConnector`, `Utility`, `Persistence`, `Aggregation`, `OOCConnector`, `ITConnector`. Methods: `Pub`, `Get`, `Set`, `Del`, `Call`, `Reply`. Only the topic forms of MG 9.1.x/9.2.x are allowed (`oec/spec/matrix/method-resource.yaml`), any other form is invalid; `Metadata` always with `Source` and `Tag`; `Call`/`Reply` with optional `Source`, never a `Filter`, `Reply` topic = `Call` topic with the Method swapped. | MG 7, 7.2, 7.4, 9 |
| G-2.6 | Payloads follow **OPC UA Part 14/6 V1.05.04** JSON with the **fixed content masks of MG 8.1.4** (no PubSub configuration is exchanged): `ua-data` (NetworkMessage), `ua-metadata` (DataSetMetaData), `ua-action-request` / `ua-action-response` (ActionNetworkMessage, replaces `MSG`). **`NodeId`s are JSON strings** per Part 6 V1.05 5.1.12: namespace 0 as `"i=<id>"`, other namespaces only as `"nsu=<uri>;…"`, never `ns=` and never the V1.04 object form (GL-ADR-013). `Messages` is always an array. DataSet payloads use VerboseEncoding + RawData; Actions use CompactEncoding. All keys PascalCase; OI4-defined objects **must not be extended**. `ReplyTo` in `ua-metadata` is the only OI4-specific key. | MG 8.1, 8.1.4, 8.2, 8.2.6, GL-ADR-006/007/013 |
| G-2.7 | `PublisherId` = `<ServiceType>/<IdentificationLink>`; `MessageId` = `<unixTimestampInMs>-<PublisherId>`, globally unique; consumers treat it as an **opaque** string (compare only). **`ReplyTo`** (replaces `CorrelationId`) is mandatory in `ua-data`/`ua-metadata`: `""` if not caused by another message, otherwise the `MessageId` of the causing message (passed on along chains). Actions correlate via `CorrelationData`, `RequestId`, `RequestorId`, `ResponseAddress`; `PublisherId` of request and response is the Responder. | MG 8.2.1, 8.2.2, 8.2.16–8.2.18, GL-ADR-005/007 |
| G-2.8 | Every `DataSetMessage` carries **`DataSetWriterName`** (= unencoded IL of the asset, corresponds to topic `<Source>`; replaces `Source`) and **`WriterGroupName`** (= topic `<Filter>`, `""` if the resource has no filter; for `PublicationList`/`SubscriptionList` entries always `<ResourceType>[/<Tag>]` of the entry, e.g. `Data/oee`, `MAM` (GL-ADR-018); replaces `Filter`). Not used in Action messages. `Status` is a StatusCode object `{Code, Symbol?}`, sent only if not Good (missing = Good; receivers evaluate `Code` only; ActionResponse uses CompactEncoding, `{}` = Good). `MetaDataVersion` and `MinorVersion` are mutually exclusive. `MessageType` optional (`ua-keyframe` default, `ua-event` for Event). | MG 8.2.3, GL-ADR-004/006/018 |
| G-2.9 | Predefined `DataSetClassId`s (MG A2) are used verbatim; IDs of removed resources and Actions are reserved and never reused. A `NetworkMessage` always carries the `DataSetClassId` of the resource addressed by the topic (also for `Get` and with helper DataSets). For `Data`/`Metadata` the publisher defines it, stable per DataSet structure across restarts. | MG 8.2.1, A2 |
| G-2.10 | `DataSetWriterId` is UInt16, unique per publisher, one per combination of resource + `DataSetWriterName` + `WriterGroupName`; **0 is invalid**; 1–9 reserved: 1 PaginationRequest, 2 Pagination, 3 Locale (helpers: `WriterGroupName` = helper name, `DataSetWriterName` = IL of the publishing app), 4–7 reserved for future common services, 8 `NewDataSetWriterId` (`ActionTargetId` 1); applications start at 10. DSWIDs may change on restart – consumers re-resolve them. **Only common service: `NewDataSetWriterId`** (GL-ADR-012). | MG 8.2.2, 8.2.3, 8.4.1, GL-ADR-012 |
| G-2.11 | MQTT: v3.1.1 as minimum, no MQTT 5 features required, TLS ≥ 1.2 only (default port 8883, no plain 1883), auth via username/password or client certificate (cert wins), QoS 0 default, **no retained messages**, clean session `true`, keep-alive 60 s, ClientId = container name/hostname. TLS/auth mandatory at all levels; remaining client behavior mandatory at Level 3, recommended at Levels 1–2. | MG 6.1–6.4, 1.3 |
| G-2.12 | Lifecycle: Birth = `MAM` of the application on every connect; Will = `Health` `FAILURE_1`/0; Close = `Health` `NORMAL_0`/0 before graceful disconnect; Birth to `Pub/MAM/<AppId>`, Close/Will to `Pub/Health/<AppId>`; without `Timestamp`/`SequenceNumber`. Subscribers interpret Close as offline (graceful), Will as offline (ungraceful), online again after the next Birth. Birth + Will mandatory from Level 1. `Health` (incl. optional `Details[]`) is published on start, on any change (also of a `DetailObject`) and every 60 s; `Health` = most severe status. Birth topic and Health timing carry "must" since SF-035 (C-016). | MG 6.3.3–6.3.5, 7.5.1, 8.3.2, GL-ADR-001, SF-035 |
| G-2.13 | **Compliance levels** (GL-ADR-009) per domain; the domains are **independent** – a level in one domain neither requires nor implies a level in the other (e.g. microcontroller: Messaging L3, no Service Container level; container: Service Container L3 with Messaging L1; SF-038). Messaging: **L1** `Pub` of `MAM` + `Health` (self + subordinate assets), Birth/Will, TLS/auth, topic + payload format; **L2** + `Get` (MAM/Health via Get) and `Set`/`Del` where applicable (resources offered for modification), all other resources and `Call`/`Reply` + `NewDataSetWriterId` recommended; **L3** = **all** methods, resources and common services (applications: 10 resources incl. `Config`, `Data`, `Metadata`, `Event`, `SubscriptionList`; devices: 8, without the lists), `Set`/`Del` for every resource they are defined for. **Resources without content:** `Get` is answered with an empty list (`"Messages": []`), no `Pub` on its own (SF-037). `Get` of `Metadata` without `Data` ⇒ no `Metadata`, may answer `Event` Status `Bad`/`BadNotFound` (SF-039). `Set`/`Del` offered ⇒ `Event` category `Status` mandatory from L2, recommended at L1; `Set`/`Del` on an unknown object ⇒ `Event` Status `Bad` (must from L2, should at L1). "OI4 compliant" without level = L3. The level is **declared by the manufacturer** per domain (no bus message); tests are grouped per level and the declared level is a test-run parameter (incl. lower levels); a registry may show an informative *observed* level. Removed in 2.0: License, LicenseText, RtLicense, Interfaces, SBoM, NE107 (ADR-0005, GL-ADR-008). | MG 1.3, 7.2, RIG 1.2 |
| G-2.14 | `Set`/`Del` only on fully qualified topics; every `Set`/`Del` **must** be answered by a `Status` event from Level 2 on, **should** at Level 1 (MG 7.4, SF-037 amended C-016), whose `ReplyTo` **must** be the request's `MessageId` (MG 8.2.1). | MG 7.4, 8.2.1, 9.1.x, SF-035, SF-037 |
| G-2.15 | Messages must respect the broker's `MaxPacketSize` (bytes, min 262144); larger result sets use Pagination (`PaginationRequest` on `Get`, `Pagination` on `Pub`, linked by `PaginationId`). | RIG 4.1.1, MG 8.3.11 |
| G-2.16 | Container storage contract (Service Container Compliance, mandatory at L3, recommended at L2): `/etc/oi4/mqtt` (`broker.json`, `broker.pem`, `broker_ca.pem`), `/etc/oi4/certs` (`ca.pem`, `<containername>.pem`), secret storage `/run/secrets/oi4` (identity of the application, GL-ADR-022: `credentials` base64 `user:pass`, `private_key.pem` of `<containername>.pem`, `passphrase`; one per container), `/etc/oi4/app` (config), `/opt/oi4/app` (data), **`/opt/oi4/licenses`** (exactly one of `sbom.spdx.json` / `sbom.cdx.json`, license texts in the SBOM or as `<License-ID>.txt`; shipped in the image; mandatory from L2). OCI image mandatory at all levels for containerized components. | RIG 1.2, 4.1, 4.2, GL-ADR-002, GL-ADR-022 |
| G-2.17 | Each `Filter` level is a `<Topic encoded String>`: `+`, `#`, `/` inside a level are percent-encoded (`%2B`, `%23`, `%2F`, and `%` as `%25`), no other characters are encoded; upper-case hex digits, so `%` only occurs in these four sequences. `/` only separates the levels defined by the resource (`<ResourceType>/<Tag>`, `<EventCategory>/<EventLevel>`), never leading/trailing, no empty level. In `<ResourceType>/<Tag>` (only for `Data`, `Metadata`, `Config`, `Event`) the `<Tag>` is the complete `Filter` of that resource, e.g. `Event/Syslog/Notice`. `WriterGroupName` uses the same value. Event categories (closed set) `Syslog`/`Status`/`Generic`; Status event level = `Good`/`Uncertain`/`Bad`; Generic level free. | MG 7.7 |

## G-3 Process

| ID | Rule |
|----|------|
| G-3.1 | Work happens in **cycles** (see `README.md`). No cycle without a log file; no cycle is done without updated `STATUS.md`. |
| G-3.2 | **Small steps.** One phase at a time; a new phase starts only after the product owner confirmed the exit criteria of the previous one (or explicitly allowed overlap). |
| G-3.3 | **Traceability:** every schema rule, SDK behavior and test references the guideline section and, from Phase 1 on, a requirement ID (`REQ-…`). |
| G-3.4 | **Ask before deciding** (product owner; the PO also decides spec interpretations, ADR-0007) for: choice of language/runtime/framework, repository layout, public API shape of the SDK, interpretation of ambiguous spec sections with protocol impact, licenses, anything changing scope. Record the answer as an ADR. |
| G-3.5 | Spec ambiguities are never silently resolved. Log them as `SF-xxx`, propose an interpretation, mark it in code/schema with the SF id, and keep the decision reversible. |
| G-3.6 | Language: communication with the product owner in German; all artifacts (code, comments, docs, logs, ADRs, commit messages) in English. |
| G-3.7 | Handover-ready at all times: another agent must be able to continue using only `AGENTS.md`, `STATUS.md` and the latest log. |
| G-3.8 | **Version control:** the workspace is a local git repo (ADR-0012); every change is committed individually, referencing the cycle and REQ/SF/ADR ids. Nothing is pushed/published without PO approval; working assumption: private GitHub repositories only, CRA review before any public release (Q-011). Deployables live only in `oec/`. |
| G-3.9 | **Test data is reviewed by the PO per increment:** test vectors in `oec/spec/vectors/` (and later the schema vectors of D1) carry `status: draft` until the PO confirms them (`reviewed`). Every vector change against its guideline source is listed in `edits`; deviations from the guideline become spec findings (ADR-0018 amendment C-013). |

## G-4 Engineering

| ID | Rule |
|----|------|
| G-4.1 | **Clean room, clean code:** small modules, clear responsibilities, no global mutable state, typed APIs, no dead code, no TODOs without a tracking entry. |
| G-4.2 | **Schema first / contract first:** the JSON Schema and shared test vectors (valid + invalid messages incl. topic) are the contract. The SDK, demos and registry must pass them. Test vectors are language-neutral so a second SDK can reuse them. |
| G-4.3 | **Tests are part of the deliverable:** unit tests for all protocol logic (IL encoding, topic build/parse, message build/validate, pagination, lifecycle); integration tests against a real broker (containerized, TLS). |
| G-4.4 | **Current stable tooling and dependencies** only, few dependencies, no abandoned packages; lock files committed; reproducible builds. |
| G-4.5 | **Secure by default:** TLS mandatory; any insecure mode must be explicit, dev-only and loudly logged. No secrets, keys or real credentials in the repo. Sensitive config values (`Sensitive=true`) never logged. |
| G-4.6 | **Developer experience is a primary goal of D2:** usable at every compliance level (L1 smart device without container contract … L3 full container app); microcontrollers are served by the separate micro SDK D9 in C17 (reference: ESP32/ESP-IDF, ADR-0016/0017), sensible defaults from the container storage contract, minimal boilerplate, helpful error messages that reference the guideline section. |
| G-4.7 | **Demos must run without paid or registration-bound external services** (weather demo: keyless API, plus an offline simulation fallback). |
| G-4.8 | **Containers:** OCI images, multi-arch (amd64, arm64; armv7 if feasible), non-root user, container name = hostname convention honored, **SBOM (`sbom.spdx.json` or `sbom.cdx.json`) + license texts (`<License-ID>.txt`) generated at build time into `/opt/oi4/licenses`** (RIG 4.1.4; our own containers target Service Container Compliance Level 3). |
| G-4.9 | **Versioning:** SemVer for all artifacts; JSON Schema `$id`s carry the guideline major version (2.x). |
| G-4.10 | **License:** MIT for all new artifacts (ADR-0004). New dependencies must have MIT-compatible licenses. |
| G-4.11 | Docs are written for newcomers: start with a working example, explain concepts after. The docs site (`oec/docs`) is **standalone – no hyperlinks to the guideline site**; guideline sections may be referenced by number (ADR-0012). |
| G-4.12 | **Verifiable by D7/D8:** every runtime artifact (SDK example app, micro SDK example, demos, registry) must pass D7 at its declared Messaging level and – if containerized – D8 at its Service Container level (ADR-0016) in CI. The tools' verdict is based on the guideline (REQ ids), never on SDK behavior. D7/D8 share **only the D1 JSON Schemas and the spec baseline `oec/spec/`** (REQ catalog, topic grammar, matrix, guideline-derived vectors; ADR-0018) with the SDKs – no code, no SDK-derived fixtures (ADR-0006). |
| G-4.13 | **Cross-platform tooling:** D7, D8 (and any developer CLI) must run on Windows and macOS (plus Linux for CI); no shell-specific scripts as the only entry point, paths and line endings handled portably. |
