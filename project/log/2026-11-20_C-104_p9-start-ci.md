## Agent decisions (G-3.4 b)

A-536 … A-545 are ADR-0032 §1 … §10 (platform, one entry point, generated workflows, CI policy, tool pins, workflows and runners, `.gitattributes`, the guideline in CI, local verification, cycle cut). New in the Linux runs:

Observed, not changed (rule 1): `oec-check` runs the restart hooks without a time limit of its own (`--restart-wait` starts after the hook); a candidate for the hardening of D7 if the PO wants it.

**Causes and fixes** (A-553 … A-556; test first where code changed):
- **`internal/probe` exceeded the default `go test` timeout of 10 minutes** (Linux and Windows). `TestSimFixtures` runs 61 fixtures through `oec-check test`; each mostly waits on answer and negative timeouts (~30 s) and they run in parallel up to `GOMAXPROCS` – 4 on a hosted runner, so ~8–10 minutes; on the Mac (14 cores) 133 s. No hang: at the timeout the last subtest had run 16–21 s. `oec/check.sh` (`gocheck`) and `oec/ci/conformance.sh` run `go test -timeout 30m` (A-553).
- **D7 defect, restart hook on Windows:** `--restart-cmd`/`--stop-cmd`/`--start-cmd` ran `cmd /C <command>` through Go's argument quoting, which turns `"` into `\"` – unknown to `cmd`, so a quoted path broke. Now `cmd /S /C "<command>"` with the command line as written (`SysProcAttr.CmdLine`, `shell_windows.go`; `sh -c` elsewhere, `shell_other.go`). `TestRestartHook` used POSIX quoting (`'…'`); it now uses `cmd` syntax on Windows (A-554).
- **D8 defect, `--daemon` with a Windows socket path:** `unix://C:\…` failed in `url.Parse` (invalid port), and `unix://C:/…` lost the drive letter (host `C:`). The path after `unix://` is now taken as it is; new `TestParseUnix` first (it failed), then the fix in `internal/engine/engine.go` (A-555).
- **Test-only (A-556):** the fake engine `enginetest` split a bind at every colon, so a Windows host path (`C:\…:/etc/oi4/mqtt:ro`) lost its mounts – this failed all `internal/run` fixtures, `TestLeak` and `oec-infra run`; it now parses from the right, and `TestWrite` creates a Windows bind. `TestUsage` expected the POSIX text "no such file" (now the text of the system); `TestReadStorage` compared a path suffix with `/`.

**Causes and fixes** (A-557 … A-559):
- **Test race in the Rust SDK runtime tests (A-557):** the helper `reconnect` dropped connection `n` as soon as the broker had seen its CONNECT; on the arm runner the app sometimes had not yet processed the CONNACK, so the drop was a failed connect, not a lost online connection, and the final `Online ×5` was never reached (the states showed 4 `Online` and 3 `Reconnecting`). `reconnect` now waits for `Online ×(n+1)` before the drop, as the other drop sites already did. Test only; the SDK is unchanged.
- **Runner disk (A-558):** the `ubuntu-24.04` image has ~13 GB free; the cargo targets of the gate (SDK workspace incl. the sanitizer builds, config service, registry, Go SDK with `liboec_ffi`) need more. New `oec/ci/disk.sh` (first step of the gate job) removes preinstalled toolchains the gate does not use (Android SDK, .NET, Haskell, Swift, CodeQL) – only on a GitHub-hosted Linux runner (`RUNNER_ENVIRONMENT`, `uname`), never locally or in `linux.sh`; the gate job sets `CARGO_INCREMENTAL=0`. Test first in `pipelines_test.go` (step order, env, guards).
- **Micro SDK defect – order of evaluation (A-559):** `oecm_publish(s, oecm_encode_birth(s, …, &len), len)` (and twice with `oecm_encode_health`) relied on the order in which the arguments of a call are evaluated, which C leaves unspecified. GCC on x86-64 reads `len` before the call: a check program printed `len=99` (the old value) with `gcc-14 -O0` and `-O2` on amd64, `len=42` with clang on arm64. A core built with such a compiler publishes the Birth and the Health with a wrong payload length. The host tests (clang) and the GCC step on arm64 and macOS did not show it; the existing `gcc-14 -O2 -Werror` step of the gate on the amd64 runner did (the failing check). Reproduced first in an own amd64 Ubuntu 24.04 container (old code: the two errors; fixed code: none), then fixed: encode first, then publish. All three call sites; no other C source of `oec/` has the pattern. ESP32 toolchains are GCC as well; the opt-in QEMU D7 runs of the firmware passed, so that build apparently evaluated in the harmless order (not verified per call site) – the fix makes it independent of the compiler. No released artifact is affected (nothing published). Pages: `oec/sdk/micro/README.md` (Check) and the Community page `micro-sdk/index.md` ("Checks": local and CI on Linux amd64/arm64 and macOS), guideline commit `02d5014`.
