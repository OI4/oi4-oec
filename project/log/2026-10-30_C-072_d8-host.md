## Design (agent, G-3.4 b)

- **Input.** `oec-infra host` reads the three storages of RIG 4.1 below `--root` (`etc/oi4/mqtt`, `etc/oi4/certs`, `run/secrets/oi4`). Each storage can also be given on its own. The container name comes from `--container` or `ROOT/etc/hostname` (RIG 4.2). It is meant to run inside the application container, or in a container with the same mounts; on a plain directory (a copy, the `oec/dev` sample roots) the mounts are not judged.
- **Never writes, never prints a secret.** The report lists names, modes and sizes of the storage entries; D8 reads at most 1 MiB per file.
- **Mounts** come only from the Linux mount table. Elsewhere they are `unknown`. A storage without a mount of its own fails only when D8 runs in a container, because then the platform did not map a host path to it.
- **Platform facts** are measured on the system D8 runs on, one file per OS: `facts_linux.go`, `facts_darwin.go`, `facts_windows.go`, `facts_other.go`; `mount_linux.go`/`mount_other.go`; `pipe_other.go`. All of them use only the standard library.
- **Injectable for the self-test.** The facts, the mount table, the daemon dialer and the environment can be injected (`host.Config`). The fixture suite therefore does not depend on the machine it runs on, and the per-OS readers have their own plausibility tests.
- **Manual verdicts.** RIG 5.1 contains values a tool can measure but not judge: the patch level, and a RAM size just below the nominal size. For these, a new verdict kind `Reported` produces the outcome `manual` on the requirement. The outcome `manual` already exists in both report schemas. It has rank 0, so the test keeps its outcome and the report shows the measured value for a human verdict.
- The full record is ADR-0025 amendment C-072 and DESIGN §9 "As built (C-072)".

## Spec findings

- **SF-116** (open, register `61e0b0f` on `feature/spec-findings`; guideline text unchanged, baseline stays `b955783`): RIG 5.1 – unit and reference of "1 GB RAM" and "4 GB non-volatile memory".
  - GB could mean 10^9 or 2^30 octets, and the minimum could refer to the installed (nominal) size or to what the OS can use.
  - A board with 1 GiB RAM shows about 0.9 · 10^9 octets to Linux.
  - Proposed: GB = 10^9 octets, nominal size of the installed memory; text addition in RIG 5.1.
  - D8 implements the proposal with manual bands (messages cite "SF-116") → **D-1**.
- RIG 4.1.1 … 4.1.3 (storages) and RIG 5.1 (platform) were checked against the implementation. Apart from SF-116 there is no contradiction.
- "Current patch level" (REQ-PLT-003) is not machine-checkable, but it is not undefined either: it is judged manually, and the REQ already has `verification: [d8, manual]`. Not an SF.

## Risks and open technical points

- Mounts are judged only on Linux. On a plain directory, and on macOS/Windows, they are `unknown`. D8 has to run inside the application container (or with its mounts) to judge REQ-CNT-001/006/008 fully. T8-HST-03 (C-073) will also read the mounts through the Engine API.
- In a container the interfaces and the os-release are those of the container, which is why both are judged manually. A run with `--network host` and a host root shows the host.
- The Windows facts and the named pipe dial have not run on Windows here (vet/build only); this needs the P9 CI matrix.
- The manual bands depend on SF-116.
