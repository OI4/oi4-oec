### Agent decisions

1. **SF-101 scoped to requestable resources.** The proposed interpretation said, without scope, that every `Mode` except `OFF_0` allows `Get`. MG 8.3.8 also says that `Event` entries (`FILTER_4`) cannot be requested, and MG 9.1 lists which resources answer `Get`. An unscoped sentence would contradict both. Both new sentences therefore start with "For resources that can be requested with `Get`". This deviates from the accepted wording, so it is review point R-4.
2. **SF-103 opened instead of changing the examples.** The accepted recommendation ("publishers should use the combined values") is not followed by the guideline's own examples: 13 PublicationList entries in MG B1.1.8 (12) and B2.6 (1) use `APPLICATION_SOURCE_FILTER_8`. Changing examples was not part of the PO order, so the agent opened SF-103 (editorial, open) with the proposal to use `ON_REQUEST_APPLICATION_SOURCE_FILTER_15` and to keep `FILTER_4` for `Event`. Review point D-1.
3. **REQ-TOP-028 revives the rule of REQ-TOP-007.** REQ-TOP-007 was withdrawn in C-020 because the guideline had no rule for the `ServiceType` of a smart device. SF-102 now gives one. The withdrawn REQ stays `deprecated` (ids are never reused) and gets `replaced_by: REQ-TOP-028`.
