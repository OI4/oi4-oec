## P5 plan and cycle cut (agent decision G-3.4 b)

ROADMAP P5 "Plan (C-062 …)": eight increments, cycles C-062 … C-068.

1. engine, simulated CUT, `test` CLI with the bus attachment, T7-GET-01/02/05/09 (C-062);
2. the rest of `Get` (GET-03/04/06/07/08, ADR-02/03) (C-063);
3. the write side, T7-SET-* except SET-10, with restore and the state model (C-064);
4. the Action T7-ACT-* and the deferred monitor rules T7-MON-09, 13 … 17 (C-065);
5. the proxy attachment, T7-CON-*, LIFE-01 … 03 (C-066);
6. restart hook, peer, `--announce`, LIFE-04, SET-10, ADR-01 (C-067);
7. + 8. `list`/`explain`, `report.schema.json`, coverage report, the P5 exit run (C-068).

Reasons:

- Increment 1 carries the whole infrastructure (engine, simulated CUT, CLI, the verdict rules of a test run). So it takes only four tests – the smallest set that exercises discovery, correlation, positive and negative exchanges and the fixture contract.
- The `Get` tests change no state on the CUT, so they come first.
- The write tests change state and need a restore. They bring the state model (PublicationList, Config) that the deferred passive rules need (3 → 4).
- Proxy (5) and restart hook/peer (6) are separate attachment modes with their own infrastructure. They are independent of 2–4.
- `list`/`explain` and the report schema freeze interfaces, so they come last, together with the exit run.
- The CI on three OSes moves to P9 together with the SDK platform matrix (D-1 (a)); the P5 exit records the local runs.

## Work

### 1. `internal/probe` – the active runner

- `probe.go`: test list (`Implemented`), options (`--level`, `--timeout`, `--tests`, tester IL), `Run`/`RunBus`, discovery, and T7-GET-01/02/05/09.
- `session.go`: the bus session (one subscription `Oi4v2/#`, QoS 1; every message goes first to the observer, i.e. the monitor engine + recorder, then to the runner) and the request/answer correlation by `ReplyTo`.
- `judge.go`: the verdict of a test run (merge with the monitor results, skip rules).
- The tests:
  - T7-GET-01: Get MAM and Health, with and without Source, for the application and up to 20 subordinate Sources; answers correlated, Sources complete. REQ-BUS-003, CMP-015, CMP-017, MSG-015, RES-HEALTH-006, RES-MAM-021
  - T7-GET-02: every resource listed in the Profile of the application answers; the Profile lists the resources of the level. REQ-CMP-018, CMP-021, RES-PROFILE-002/004.
  - T7-GET-05: a Get without content returns an empty list (Data with the filter `oecCheckNone<hex>`, else Config). A Get for an unknown Source (`oi4.org/oec-check/D7/unknown-<hex>`) gets no Pub but the Event Status Bad (`BadNotFound`). REQ-CMP-041, CMP-047; CMP-044 (MAY) is not stimulated.
  - T7-GET-09: a Get MAM with an unknown top-level key is answered like the same Get without it. REQ-MSG-046.
- `ForApp`/`NotFound` moved from `cmd/oec-check` into `internal/monitor`, because the runner needs them.

### 4. `oec-check test`

- Flags of `monitor` (connection, `--app`, `--level`, `--allow-skip`, `--max-packet-size`, `--record`, `--format`, `--report`, `--config`) plus `--timeout` (10 s), `--tests` (ids or globs, comma-separated or repeatable) and `--tester-il`. `--replay`/`--duration` are not flags of `test`.
- Usage checks:
  - `--app` is required, and the ServiceType must be one of the seven;
  - the AppId must be a valid IL, and the usage error gives a hint on dnp encoding;
  - `--tester-il`, level, format and timeout are checked;
  - every `--tests` pattern must match a test.
- `monitor.go` refactored without a behaviour change:
  - the shared flag set `newMonitorFlags(name, …)`;

  - `writeReports`.
- Report: monitor report version 1 with `"mode": "test"`, `tester` and `requests`. The text header shows "tester …: N request(s), M answered".

## Defects found (test-first, fixed)

- **D7's requests used QoS 1.** The new tester-violation check in `sim_test.go` found it: REQ-MQTT-017 makes QoS 0 the default for requests. The probe now publishes with QoS 0 and the check is green (A-154).
- `sim_test.go` failed under `go test -run` with a filter (the coverage check saw only part of the fixtures). The coverage check now runs only when every fixture ran.
- Live, a plain `OEC Demo` in `--app` was rejected as an invalid IL; correct, since the Oi4Identifier elements are dnp-encoded (SF-104). The usage error now names the encoding (`OEC,20Demo`).
