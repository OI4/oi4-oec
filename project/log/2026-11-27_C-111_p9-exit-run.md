### 2. MSVC smoke test (A-624)

The link of `hello.exe` against `oec_ffi.lib` on `windows-2025` reported `LNK4098: defaultlib 'msvcrt.lib' conflicts with use of other libs`, resolved the CRT symbols from `libucrt.lib` (static) and left the `__imp_*` imports of the aws-lc objects and of `hello.c` unresolved (`__imp_getenv`, `__imp_strtol`, `__imp__wassert`, `__imp_fputs`, …). Cause: the clang driver (GNU mode, MSVC target) always adds `-defaultlib:libcmt -defaultlib:oldnames` to the link line, also with `-fms-runtime-lib=dll` – reproduced with LLVM clang 21.1.1 `--target=x86_64-pc-windows-msvc -fms-runtime-lib=dll -###`. The static CRT then shadows the DLL CRT (`ucrt.lib`) that every object imports. Why the same line links on `windows-11-arm` the log does not show (search order of the default libraries); the fix is the same for both. `sdk-rust.sh` links with `-Wl,-nodefaultlib:libcmt`; the objects' own `msvcrt`/`oldnames` directives pull the DLL CRT. No test in `oec/ci` covers a script's link line; the evidence is the `-###` comparison (the flag removes `libcmt`) and the hosted run: `sdk` 42091300301 green on all 12 jobs, the smoke test on both MSVC runners prints the expected `build: bootstrap: no hostname …`. `oec/ci/README.md` and the Community page `sdk/c.md` name the clang flags for users of the prebuilt MSVC library.
