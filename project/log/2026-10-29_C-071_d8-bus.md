## Design (agent, G-3.4 b)

- **Connection.** `oec-infra bus` takes the connection flags of `oec-check monitor`, duplicated in `cmd/oec-infra` (the CLIs share no command code).
  - D8 opens several connections with random ClientIds, so it has no `--client-id`.
  - D8 publishes only on its own probe AppId `Utility/oi4.org/oec-infra/D8/<12 hex>` and on its two probe components. A run never writes to an application of the platform (A-250).
- **Second client.** `--credentials-2 FILE` (format of `run/secrets/oi4/credentials`) or `--bus-storage-2 ROOT` (A-251).
- **T8-BUS-01 (A-252, A-253).**
  - Raw TLS handshakes with `crypto/tls`: exactly 1.2 and exactly 1.3 (one must succeed), 1.0 … 1.1 (must fail). Every probe presents the client certificate of the run.
  - Plain-text listener on `--plain-port` (default 1883).
  - Certificate chain against the CA of the run.
  - MQTT 3.1.1 CONNECT.
  - MaxPacketSize probe per SF-105: one QoS 1 PUBLISH with a payload of exactly MaxPacketSize on a topic padded to 65535 octets.
- **T8-BUS-02 (A-254).**
  - First a positive control: D8 sends the requests itself and must receive them.
  - Then the unprivileged client sends Set of six resources, Del of two and Call NewDataSetWriterId to the probe AppId.
  - A request that arrives violates REQ-GEN-001 and the requirement of the resource.
  - A readable Set/Config warns REQ-RES-CONFIG-026.
- **T8-BUS-03 (A-255).**
  - The Registry comes from `--registry`, or D8 discovers it on `Oi4v2/Registry/+/Pub/#` within `--registry-wait` (65 s).
  - Two probe components announce themselves; D8 sends Get MAM/Health with and without Source.
  - Then D8 sends Close for the first component and triggers the Will of the second; neither may be listed afterwards.
  - No Registry → inconclusive. Whether a platform needs a Registry is T8-HST-04.
- **Self-test (A-256).** `mqtttest` gains additive options; `NewBroker` and the D7 gate are unchanged. `internal/bus/registrytest` simulates the Registry with seven faults. 28 scenarios in `testdata/bus/index.yaml`.
- **Report (A-257).** The key `broker` is added to `infra-report.schema.json` additively; report version 1.
- **Dev broker ACL (A-258).** See "Runs".
- The full record is ADR-0025 amendment C-071 and DESIGN §9 "As built (C-071)".

¹ depends on SF-115 (D-1).

`packet-limit` arithmetic (SF-105): the payload is MaxPacketSize and the topic is 65535 octets. At 262144 octets the packet is 327687 octets: 1 fixed header + 3 remaining length + 2 topic length + 65535 topic + 2 packet id + 262144 payload. SF-105 allows MaxPacketSize + 65544. Because the remaining length takes only 3 of the 4 octets SF-105 allows for, a limit 1 octet below the allowance is not observable. The fixture therefore sets the limit 2 octets below.

### Defects found by the live runs (fixed, test first)

1. **TLS probes without the client certificate.**
   - Symptom: on 8884 (`require_certificate true`) the TLS 1.2 handshake failed because no certificate was presented, so only TLS 1.3 was reported.
   - Risk: a refused 1.0/1.1 handshake could be a false "checked".
   - Tests first: new scenarios `T8-BUS-01/mtls` (positive) and `T8-BUS-01/mtls-tls11` (negative), and `TestClientCertTLS`; all failed before the fix.
   - Fix: `protocol.go` loads the certificate with `mqttwire.TLSConfig` and passes it to every handshake. An unloadable certificate makes the run inconclusive.
2. **Dev ACL without `Reply`.**
   - Symptom: the demo apps answer `NewDataSetWriterId` on `Oi4v2/<st>/<app>/Reply/NewDataSetWriterId`; the ACL denied it, so D7 T7-ACT-01/02/04 failed.
   - Tests first: `TestACL` requires `pattern write Oi4v2/+/+/Reply/#`.
   - Fix in `acl`, the conf comment and the dev README.
   - D8 does not check over-restrictive ACLs: no REQ requires that a broker allows a topic. This is a possible later note, not an SF.

### CONFIG-026 on `oec/dev` (not an SF)

Mosquitto patterns cannot bind the AppId level of a topic to a user, and applications read their own `Set/Config`. So every authenticated client can read Set/Config, and T8-BUS-02 warns REQ-RES-CONFIG-026 (SHOULD). This is a limitation of the dev environment; the guideline is consistent (A-258).

## Agent decisions (G-3.4 b, for information: REVIEW A-250 … A-258)

- **A-250** Command and connection flags as `oec-check monitor`, no `--client-id`, own probe AppId.
- **A-251** Second client `--credentials-2`/`--bus-storage-2`; without it, or with the same identity, T8-BUS-02 is inconclusive.
- **A-252** TLS/plain/certificate probes. A plain port fails only with a CONNACK; an open port without a CONNACK is a note.
- **A-253** MaxPacketSize probe (SF-105). The source is `--max-packet-size`, then `broker.json`, then 262144 with a note. Above `--max-probe-size` (64 MiB) the probe is inconclusive.
- **A-254** ACL probe set and positive control. A denial may be silent, a SUBACK 0x80 or a disconnect.
- **A-255** Registry discovery (65 s = one SF-106 heartbeat plus slack), probe components, Close/Will polling up to 3 × `--timeout`; no Registry → inconclusive.
- **A-256** Self-test: `mqtttest` options, `registrytest` (7 faults), 28 scenarios.
- **A-257** Report key `broker`, additive, version 1.
- **A-258** Dev ACL including `Reply`; the CONFIG-026 limitation.
- **Cut:** `host` (increment 3) is not pulled forward. It is a different building block (file system, permissions, `broker.json` schema) and has its own cycle C-072 in the plan.

## Risks and open technical points

- T8-BUS-03 cannot be checked against a real Registry before P7. The simulated Registry follows the D-ADR/MG text; the P7 exit run will show the gap, if any.
- The MaxPacketSize probe sends about MaxPacketSize + 65 KiB. `--max-probe-size` limits it for brokers with large limits.
- Mosquitto cannot express a per-AppId ACL. A production platform needs a broker or plugin that can, otherwise REQ-RES-CONFIG-026 warns.
- On 8883, `--plain-port 1883` finds nothing listening (port not published). An open port that never answers CONNACK only gives a note.
