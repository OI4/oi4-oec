## Goal

Messaging Level 3 in the C17 core: what REQ-CMP-010/033 demand of a device beyond Level 2 – the ReferenceDesignation (`Get` with Query, `Set`, `Del`, persisted, REQ-RES-REFDES-002) and the Action `NewDataSetWriterId` (`Call`/`Reply`, MG 9.2.1) – with persistence over the PAL; the core is judged by D7 `oec-check test --level 3` in the gate.

## What was done

1. **Core, new source** `oec/sdk/micro/src/oecm_l3.c` (609 lines; C17, no heap, no stdio, the symbol allowlist of ADR-0030 §2 unchanged), with the decisions of the Rust provider (`oec-core` `provider/refdes.rs`, `provider/actions.rs`):
   - **ReferenceDesignation** (MG 8.3.10): `Get` (also with the Query DataSetMessage, id 9, for the direct children of a `Parent`; only without a Source level), `Set` and `Del`, each answered with a Status event; an accepted change is published with `ReplyTo` and saved (`oecm.refdes`). The object is validated, then encoded in canonical form (validate pass, encode pass) into the application's buffer `refdes_buf`; DateTime values are checked (RFC 3339).
   - **`Call NewDataSetWriterId`** (MG 9.2.1): the strict request check of the Rust responder (MessageType, PublisherId = the called application, RequestorId, ResponseAddress = the Reply topic of the Call topic, base64 `CorrelationData`, `TimeoutHint` > 0, items with `ActionState` 1 and 16-bit ids); new ids above the own definitions with Ttl 60 s; a request for a foreign Source → `BadNotFound`, unknown `Resource` → `BadInvalidArgument`, a save error → `BadInternalError`, more than 256 ids in 60 s → `BadResourceUnavailable`; the reserved limit is persisted in blocks of 256 (`oecm.wid`) and wraps after 65535 to the first id; replies that do not fit one message are split.
   - `oecm_init` at Level 3 (`oecm_device.c`): `persist_load`, `persist_save` and a `refdes_buf` of at least `OECM_REFDES_MIN` (128) octets are required (`OECM_E_ARG`); both records are loaded (`OECM_E_PAL` on a load error; a stored ReferenceDesignation that is not valid canonical JSON is ignored); `OECM_E_NOSPACE` if the usable ReferenceDesignation size is below the minimum.
   - Hooks in `oecm_res.c` (Profile with `ReferenceDesignation` and `NewDataSetWriterId`, PublicationList entry `ON_REQUEST_SOURCE_10`, SubscriptionList with `Call/NewDataSetWriterId`, the publication on change) and `oecm_req.c` (dispatch).
2. **API** (`include/oecm.h`, additive): `oecm_config.refdes_buf`/`refdes_cap`, `OECM_REFDES_MIN`; the `persist_*` contract of `oecm_pal` (keys `oecm.refdes` and `oecm.wid`, `*len = 0` for a missing record, `len` 0 deletes) documented; ADR-0022 amendment C-095.
3. **Unit tests:** `tests/test_level3.c` (15 tests: lists at L3 and L2 unchanged; init arguments, `OECM_E_PAL`, `OECM_E_NOSPACE`, an invalid stored record; `Set` publish/answer/persist/unchanged/restart; the `Set` errors `BadDecoding`, `BadOutOfRange`, `BadInternalError`, `BadNotFound`; `Get` with Query; `Del`; `Call` with new ids, `CorrelationData`, own Source, no reuse after a restart, an invalid persisted limit, the error codes, the rate limit, ignored requests, 200 items split into 4 messages of at most 8 KiB; DateTime); the recording PAL `tests/fake_pal.c` stores records (with fail switches); `test_device.c`: Level 3 without persistence → `OECM_E_ARG`. All **87 Unity tests** pass under ASan + UBSan.
4. **Payload check:** `tests/emit.c` adds a Level 3 lifecycle (`Set`, `Get`, `Get` with Query and an invalid `Set` of the ReferenceDesignation; three `Call`s – with `CorrelationData` and an unknown Resource, with the own Source, with a foreign Source); D7 `oec-check validate`: **69 messages, 0 invalid** (4 `pub-referencedesignation`, 3 `reply-newdatasetwriterid`).

## Agent decisions (G-3.4 b)

- **A-458 Level 3 contract:** at Level 3 `oecm_init` requires `persist_load`, `persist_save` and a ReferenceDesignation buffer of at least `OECM_REFDES_MIN` (128) octets (`OECM_E_ARG`), loads both records (`OECM_E_PAL` on a load error) and ignores a stored ReferenceDesignation that is not in canonical form; Level 3 no longer returns `OECM_E_LEVEL` (A-453 ends).
- **A-459 ReferenceDesignation size:** the usable size is the minimum of `refdes_cap`, half the transmit buffer and the room of a whole answer (paged answer minus a 320-octet reserve for `ReplyTo`); a larger object → `BadOutOfRange`. The core keeps one canonical JSON form (`\b`/`\f` written as `\u0008`/`\u000c`); it is published on change only, not at connect (as Rust `refdes_pending`).
- **A-460 `NewDataSetWriterId`:** new ids start after the ReferenceDesignation id (above all definitions); the limit is persisted in blocks of 256 (one save per 256 ids) and wraps after 65535 to the first id; at most 256 ids per fixed 60 s window (`BadResourceUnavailable`); replies are split over several messages when they do not fit.
- **A-461 Strict request check as serde:** duplicate fields make a `Call` ignored, `null` counts as absent, an array-form `Payload` is not accepted, DateTime values up to 64 octets are decoded; requests to the ReferenceDesignation and `Call` topics with a Filter level are ignored at every level (Rust: Filter forbidden; a small change at Level 2, where such a request was answered before).
- **A-462 Profile:** `NewDataSetWriterId` is listed from Level 3 only (Rust lists it from Level 2): the micro core serves `Call` only at Level 3 (REQ-CMP-033), so a Level 2 device does not announce it.
- **A-463 No persisted Config values in the core:** only the ReferenceDesignation must survive a restart (REQ-RES-REFDES-002); Config values live in the application (A-447), which saves them in `on_config` if it needs to. This replaces "persisted Config values" of the C-094 plan.
- **A-464 Host runner state and D7 seeding:** `-state` directory with one file per record and atomic rename; `d7run.Files` writes files below the storage root; the D7 Level 3 run starts with a stored ReferenceDesignation, so T7-SET-04/10 and T7-MON-14 run (50 pinned passes). All three D7 runs stay in the gate (different code paths); step 9 takes about 5 min.
- **A-465 Fuzzing and emitter at Level 3:** `fuzz_message` runs a Level 3 device (in-memory store reset per input) with 6 new seeds; the emitter adds a Level 3 lifecycle.
- **A-466 Sizes:** state 600 octets on 64-bit, 568 on Cortex-M4 (of 1024); Cortex-M4 `-Os` 42.3 KB code + constants (Level 3: 6.3 KB).
