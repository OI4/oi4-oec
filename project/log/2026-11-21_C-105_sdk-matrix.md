### 2. Go SDK on Windows amd64 (ADR-0027 amendment C-105, A-563)

The first MinGW link of the Go examples failed: aws-lc built for `x86_64-pc-windows-gnu` uses winpthreads (`pthread_rwlock_*`, `pthread_once`, `nanosleep`, …), and `rustc --print native-static-libs` does not list it because the Rust standard library links it itself. Test first `TestLinkFlags` (every supported GOOS/GOARCH has its library and system-library flags), then `link.go` for windows/amd64: `-L${SRCDIR}/lib/windows_amd64 -loec_ffi` and `-lbcrypt -lkernel32 -lntdll -luserenv -lws2_32 -ldbghelp -l:libpthread.a` – static, so the binaries need no `libwinpthread-1.dll` (checked with `objdump -p`). `ffi-lib.sh` adds `-l:libpthread.a` to `native-static-libs.txt` of `*-windows-gnu` for C users. The README table, "Other platforms" and the Community page `sdk/go` describe it.

### 3. ARMv7 (A-564, A-568)

`sdk-armv7.sh`: clippy for `armv7-unknown-linux-gnueabihf` with aws-lc-rs and with `crypto-ring`; tests of `oec-core`, `oec` (both providers) and the Rust tests of `oec-ffi` under `qemu-arm`; `ffi-lib.sh`; the C smoke test under `qemu-arm`; the Go SDK for `linux/arm` (`GOARM=7`): vet, examples, `hello` under `qemu-arm`. The C tests of `oec-ffi` (sanitizers, a native `cc`) stay with the native runners. Result in an Ubuntu 24.04 arm64 container: **all pass** after two fixes:

- **Rust SDK test race (A-566):** `data_sets_publish_their_state` measured three cyclic publications against two Intervals; publications queued while the test was busy arrived at once under qemu (82 ms < 100 ms). The helper `next_fresh` starts the clock with the first publication the test had to wait for. Test only; the SDK is unchanged.
- **Go SDK test on 32-bit (A-567):** `provider_test.go` built a MessageId from an untyped constant above 2^31 – `go vet` for `linux/arm` failed (`overflows int`); now `int64`. Test only.
- **aws-lc-rs on ARMv7 (A-568, ADR-0023 amendment C-105):** the default provider cross-builds with the Ubuntu cross gcc and passes under qemu – `crypto-ring` is no longer required on ARMv7, only the smaller option (Community page `sdk/rust` adjusted). The ring tests had only been clippied in the gate before; they pass on macOS arm64 and ARMv7.

### Runs of `57e47ce` (sdk 41872159392, gate 41872159763, conformance 41872159674)

- `gate`: green on all three runners. `conformance`: green except `ubuntu-24.04-arm` (A-575). `sdk`: `rust` green on Linux x64/arm64 and macOS arm64/intel; `go` green on both Linux and both macOS runners; red: `rust` on both MSVC runners (A-571), `go` on `windows-2025` (A-573), `armv7` (A-572).
- **A-571 Windows `localhost` (test only):** every `oec/tests/consumer.rs` test stopped with "not reached: online". Windows resolves `localhost` to `::1` first; a refused loopback connect there takes about 2 s, the test broker listened on `127.0.0.1` only, and the SDK bounds a connect attempt (name resolution, TCP over all addresses, TLS handshake) by the keep alive – 1 s in the tests – so the client never reached IPv4. The test broker (`tests/testbroker/mod.rs`) now also listens on `::1` (best effort, the same port, one accept thread per listener, one connection counter). Test first: `test_broker_listens_on_every_localhost_address` (failed on macOS before the fix).
- **A-572 mTLS under qemu (test only):** `client_certificate_over_tls12` saw `Closed(0)` before the handshake event – under `qemu-arm` on the amd64 runner the TLS handshake with a client certificate took longer than the 1 s keep alive. Both mutual-TLS tests now use a 10 s keep alive (`MTLS_KEEP_ALIVE`); they test the certificate, not the keep alive.
- **A-573 `sdk-go.sh` (CI):** tests and examples passed on Windows, the upload found no files: the script passed the relative `dist/sdk` to `ffi-lib.sh` after `cd oec/sdk/go`. It now resolves `<dir>` first (as the other three scripts).
- **A-575 D8 endpoint (defect):** `TestEndpointLimits` saw a connection record without its handshake result. `serve` appended the record and then set the result in a second locked step; a `Snapshot` in between (the settle loop or `finish` of `oec-infra run`) could list a connection with `Handshake` "" – in the report a connection judged neither ok nor failed. The record is now listed only with its result. Test first: `TestEndpointRecordsCompleteHandshake` (200 failing handshakes while polling `Snapshot`; failed before the fix, 20 × green with `-race` after). The report schema and the documented behaviour are unchanged; the Community page needs no change.
- **Observation (for information, not changed – rule 1):** the SDK's per-attempt connect timeout equals the keep alive and covers all addresses of the host name and the TLS handshake. With the default keep alive (60 s) this is harmless; an application configured with a keep alive below ~2 s and `localhost` on Windows, or on a very slow device, would never connect. A separate connect timeout would be a small additive change of the Rust SDK – only on the PO's order.
