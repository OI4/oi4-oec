## Design (agent, G-3.4 b)

- **What `run` must observe.** The three run tests ask whether the application *uses* what the platform gives it: the Message Bus storage (T8-RUN-01: REQ-CMP-029, REQ-CNT-004), the certificate and secret storages (T8-RUN-02: REQ-CNT-009) and its container name (T8-RUN-03: REQ-CNT-021, REQ-MQTT-013). An application that ignores the storages and still reaches a broker must be caught. So every value D8 generates differs from a default: the `SecurePort` is not 8883, the broker host is not `localhost`, `broker.json` carries an element the application does not know, the password contains `:`, the private key is encrypted and the passphrase is base64, and the broker certificate is signed by a CA the application can only know from the storage.
- **Three phases, one container each.** A single container cannot show that the application handles both means of authentication and both trust anchors. So:
  - **credentials** – `broker.json` with the unknown element `OecD8Unknown`; the broker certificate signed by CA A of `ca.pem`; no `broker_ca.pem`; only `credentials`;
  - **certificate** – the broker certificate signed by CA B of `broker_ca.pem` (`ca.pem` names CA A); only `<containername>.pem` (signed by CA A) with `private_key.pem` (encrypted PKCS#8) and `passphrase` (base64);
  - **untrusted** – the storages of credentials, but the endpoint presents a certificate of CA X; the application must not complete the handshake. Only when T8-RUN-01 is selected.

  Each phase has its own container `oec-d8-run-<uuid>` (name = hostname, RIG 4.2), its own storages and its own endpoint port.
- **The test endpoint is no broker.** An own, minimal MQTT 3.1/3.1.1/5 server on the standard library and `mqttwire` (`internal/run/endpoint.go`): TLS with the certificate of the phase, the client certificate requested and verified against CA A, the login compared in constant time (it keeps no password, only the result), CONNACK, SUBACK and PUBACK like a broker but no forwarding. It records per connection the handshake, the TLS version, the client certificate, the protocol level, the client id, the means of authentication, the number and largest size of the payloads and the Birth message (Pub/MAM of the application). A packet larger than `MaxPacketSize` + 65544 closes the connection (RIG 4.1.1, SF-105). `mqtttest` was not reused: it is a broker for D7 tests with a fixed PKI shape; `run` needs three CAs per run and the observation per connection.
- **How the container reaches the endpoint.** The broker host is `oec-d8-broker`, mapped with `ExtraHosts` to `host-gateway`; the broker certificate names it. The endpoint listens on 127.0.0.1 on macOS and Windows (Docker Desktop forwards `host-gateway` to the host's loopback) and on the gateway of the bridge network elsewhere (from `GET /networks/bridge`). `--listen` and `--broker-host` override both; an IP address as broker host needs no mapping and gets an IP SAN.
- **Writing to the engine.** Four write calls and only for D8's own containers – see A-281 and ADR-0025 amendment C-074. A remote engine is refused before any request, because the storages are bind mounts of this machine and the endpoint listens here (A-282).
- **Self-test.** The fake Engine API of C-073 gains a run mode: image documents, create/start/stop/delete, and a hook that runs the simulated application (`internal/run/simapp`) in process when a container is started. The hook maps the container paths to the bind sources and resolves the broker host of `ExtraHosts` to loopback (through the new `mqttwire.Config.Dialer`); TLS still verifies the broker name. The test images are `oec-d8-sim:<fault>` (`internal/run/runtest`); for the live run the same simulated application is built as a Linux binary and loaded with `docker load`.

## Findings and fixes

- **SF-117 (open, guideline `5ae22a0`, findings only)** – RIG 4.1.3 requires the platform to provide *at least one* means of authentication (credentials, or private key with certificate); MG 6.2.2 lets a client use either. The guideline does not say which means a containerized application must *support*. An application that supports only one cannot connect to a platform that provides only the other, although both are compliant on their own. D8 cannot decide whether an application that ignores one means violates REQ-CNT-009. **Proposed interpretation:** the application supports both means and uses the one the platform provides (with both: the client certificate, MG 6.2.2); proposed text for RIG 4.1.3 after the admonition: "The application shall support both means of authentication and shall use the means that the platform provides." Until decided, T8-RUN-02 warns (message marked "SF-117") when the application authenticates in only one phase; as proposed, the warning becomes a violation. → **D-1**.
- **Remote engine only noticed after a timeout** (implementation, fixed test first): see Work 5.
- **`docker load` of the test archive on the classic image store** (implementation, fixed test first): see Work 6.

## Agent decisions (G-3.4 b, for information: REVIEW A-281 … A-291)

- **A-281 Write boundaries of the Engine API client:** `POST /containers/create`, `…/start`, `…/stop` and `DELETE /containers/{id}?force=1&v=1` only for a container named `oec-d8-…` with the label `org.oi4.oec-infra=run`; start/stop/remove inspect first and refuse a foreign container without a write. Each run labels its containers with `org.oi4.oec-infra.run=<run id>`; the cleanup lists them with a fresh context (also after a cancel or an error). `v=1` removes the anonymous volumes of D8's container with it; D8 never creates a named volume. No pull, load, build, volume, network or image call. `container` and `host` stay read-only.
- **A-282 Local engine only, never pull:** every named endpoint (`--daemon`, `DOCKER_HOST`, `CONTAINER_HOST`) must be a Unix socket, a named pipe or loopback TCP, else exit 2 before any request (the storages are bind mounts of this machine, the endpoint listens here). An image the engine does not have is exit 2.
- **A-283 Command `oec-infra run`:** flags as in the README; report key `run` (additive, report version 1) – engine, image (reference, id, OS, architecture), endpoint, cleanup problems, phases with connections and the Birth message; never a secret, a username, a log, the environment or a host path.
- **A-284 Three phases:** credentials, certificate, untrusted (only with T8-RUN-01); one container, storages and port each; CA A (`ca.pem`, client certificates), CA B (`broker_ca.pem`), CA X (untrusted). A phase ends with the Birth message plus `--settle`, a failed handshake, a refused CONNECT, the exit of the container or `--wait`.
- **A-285 Generated storages:** values that differ from every default (see Design); mounts `ro` for the Message Bus, certificate and secret storages, `rw` for the two application storages; directories 0755 (application storages 0777) and files 0644, because the application may run as any user in its image – these are D8's throw-away test storages, not a recommendation for platforms.
- **A-286 Network:** listen on 127.0.0.1 on macOS/Windows, on the bridge gateway elsewhere; broker host `oec-d8-broker` via `host-gateway`; `--listen` and `--broker-host` override.
- **A-287 Test endpoint:** own minimal MQTT server (protocol levels 3, 4, 5), no forwarding, constant-time login check, no password kept, handshake timeout 15 s, a packet above `MaxPacketSize` + 65544 closes the connection; `--max-packet-size` 1 … 268435455 − 65544 (default 262144).
- **A-288 Judging:** as in DESIGN §9 "As built (C-074)". REQ-CMP-029 repeats each observation of REQ-CNT-004/009/021 (prefixed "REQ-…: "), because RIG 1.3 makes the container environment of RIG 4.1/4.2 the Level 2 claim; a requirement without any observation is inconclusive. One means of authentication only warns until SF-117 is decided.
- **A-289 Self-test:** the fake Engine API runs the simulated application in process; its dialer refuses port 8883 so that a self-test never reaches a real broker on this machine; retries are fixed at 200 ms. Run fixtures are not part of `Fixtures()` (A-248); `COVERAGE.md` unchanged. The self-test needs Unix sockets and is skipped on Windows (like the C-073 engine tests); a Windows host (`C:\…` bind sources, named pipe) has not been run live.
- **A-290 Test images and live run:** `runtest.Archive` writes an OCI layout plus a Docker `manifest.json`; the images are built at test time, never committed and removed by tag after the live run. One opt-in script (`live.sh`) instead of a separate `live-infra.sh`.
- **A-291 Cut:** increment 6 (`list`/`explain`/coverage for D8, freezing D8 report version 1, P5b exit) is not pulled forward: freezing the report should follow the review of R-1 and the decision on SF-117, which may change the T8-RUN-02 verdicts.

## Risks and open technical points

- **Podman and Windows** are not run live (A-289); the label filter and `host-gateway` are Docker features that Podman 4+ also supports. To check in the P5b exit run or CI (P9).
- **Linux listen address:** on Linux the endpoint listens on the bridge gateway; a firewall that blocks the bridge to the host makes every test fail as "no connection". `--listen` and `--broker-host` are the escape hatch; the README names it.
- **A real application may need longer than `--wait` (30 s)** to start; then T8-RUN-01 fails with "no connection". The report shows the observation time.
- The secret storage of the sandbox is readable by every user in the container (A-285); harmless for throw-away test secrets.
