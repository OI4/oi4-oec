### 2. `oec-check validate` (`908b171`)

Module `oec/conformance` (Go, ADR-0013), packages:

| Package | Content |
|---|---|
| `internal/topic` | staged topic diagnosis: prefix, ServiceType, AppId, Method, Resource, Source, Filter against `topic-patterns.json` and the Method × Resource matrix; the failing level names its REQ (REQ-TOP-…, REQ-ACT-020); warnings for control characters/whitespace in Filter levels |
| `internal/ilink` | Identification Link checks (REQ-IL-…), base64url elements, dnp encoding |
| `internal/schemas` | strict + tolerant schema sets from `schema.FS`; error → REQ via the nearest `$comment`; R-4 mutation probes |
| `internal/rules` | R-2 (equality with topic values), R-3 (relations inside one message), R-6 (declared role) |
| `internal/validate` | one message: topic → parse → schema → rules, dedupe |
| `internal/report` | text and JSON report |
| `internal/finding`, `internal/testvec` | finding type; test helper for the vectors of `oec/spec/vectors` |
| `cmd/oec-check` | CLI: `validate`, `version`; exit codes 0/1/2/3 |

Tests: every topic, IL and dnp vector; every payload vector (valid → no finding; invalid → exactly its `violates`); the schema/rule split of `oec/schema/tests/rule-layer.yaml`; R-4 probes; CLI exit codes. Cross-compiles for windows/amd64, linux/amd64, linux/arm64, darwin/arm64 (pure Go, P2 exit 6).
