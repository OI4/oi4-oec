## Work

### 1. The tests (`internal/probe/set.go`)

**Preparation (`prepareWrite`).** Before the first write test, D7 reads:
- the Profile;
- the assets (Get MAM without Source);
- the **state**: Get without Source of Config, PublicationList, ReferenceDesignation and SubscriptionList.

**Restore check (`checkRestore`).** After the last write test, D7 reads the state again and compares it with the first reading (`Restore`: `checked`, `restored`, `changed`, `note`).

**Judging a reaction (`judge`).** The reaction is judged in two parts; the catalog entry decides which REQs a test judges:
- **Status event** with the MessageId as `ReplyTo` (REQ-TOP-014/015, REQ-CMP-023, 038, REQ-RES-EVENT-005, plus the event REQ of the resource);
- **after a successful Set: the publication** of the changed object on its Pub topic with the `ReplyTo` (REQ-BUS-006, REQ-MQTT-019, REQ-MSG-015, plus the publication REQ of the resource).

**The tests:**

- **T7-SET-01**
  - Every object the CUT offers for modification answers a Set (the write-back of what it published) with a Status event and the publication.
    - Offered means: Config, PublicationList, SubscriptionList, ReferenceDesignation, and the Data with a listed Set subscription.
  - A Data or Config DataSet that accepts a Set is listed with its Set subscription. A listed one accepts it (REQ-RES-SUBLIST-016, CMP-016): Good → checked; BadNotWritable/BadNotSupported → violation; any other outcome → skip.
  - A Del of an unknown subscription stimulates REQ-TOP-015.
- **T7-SET-02:** Set and Del of an object the CUT does not have are answered with Status Bad. For an unknown asset, the event comes under the AppId (REQ-CMP-043, SF-108).
- **T7-SET-03** (level 3)
  - Covers the Set/Del matrix of REQ-CMP-033 for the application and the represented asset.
  - Reuses the reactions of the earlier write tests and stimulates only the missing combinations with a harmless request (an unknown object, or the write-back of an existing one).
  - "Supported" = any reaction with the `ReplyTo` except BadNotSupported. Runs after the other write tests.
- **T7-SET-04**
  - After the Del of a whole object, nothing is published (REQ-BUS-007). The whole object is the ReferenceDesignation (restored with Set), or the last of two SubscriptionList entries D7 created.
  - After a partial Del (the first of the two entries), the rest is published (REQ-BUS-008).
  - The ReferenceDesignation is deleted only if a write-back Set of it got Status Good (earlier, or sent now): D7 does not delete an object it could not restore (A-189).
  - "Nothing" means: nothing until the Status event plus the grace time.
- **T7-SET-05:** Set Config writes back every Config DataSet, including the mask of a sensitive value (REQ-RES-CONFIG-025). It is rejected (CONFIG-023) for:
  - an unknown object;
  - a changed read-only property (Name);
  - a Number Value that is not a number. This is a deliberate invalid stimulus and a tester violation of REQ-RES-CONFIG-007.

  Masking in the publication: REQ-RES-CONFIG-024.

  At level 1, REQ-RES-CONFIG-025 is only SHOULD: a Config DataSet with a masked value is then not written at all (SET-01 and SET-05), and SET-05 skips CONFIG-025 for it (A-188).
- **T7-SET-06:** Set Data writes back the Data DataSets with a listed Set subscription (REQ-RES-DATA-011/012). Without one, a Set of an unknown tag (`{"D7":1}`) stimulates the Status event.
- **T7-SET-07:** Set Metadata writes back the Metadata of a Data DataSet of the PublicationList (REQ-RES-META-006/007). Without one, the Metadata of an unknown DataSet stimulates the Status event.
- **T7-SET-08:** Set PublicationList
  - writes back the configurable entries (REQ-RES-PUBLIST-024/025);
  - is rejected for a Mode change of a Config `NONE_0` entry (REQ-RES-PUBLIST-016). An accepted change is undone.
  - A Data entry set to `OFF_0` is no longer published (REQ-RES-PUBLIST-007); its Mode is restored afterwards.
- **T7-SET-09:** Set and Del ReferenceDesignation (REQ-RES-REFDES-009/010): write-back, Del, and the restoring Set.
  - Without an object, a Del stimulates the Status event.
  - If Get ReferenceDesignation was not answered, the test sends nothing destructive and skips.
  - If the write-back Set is not answered with Status Good, there is no Del: REQ-RES-REFDES-010 is skipped (A-189). The same rule holds for SET-04 and the Del stimulus of SET-03 (skip, not violation).
- **T7-SET-11:** Set SubscriptionList
  - writes back the `CONF_1` entries (REQ-RES-SUBLIST-013/014);
  - is rejected for an Interval change of a `NONE_0` entry (REQ-RES-SUBLIST-004);
  - creates an entry of D7 (optional, SF-111; REQ-RES-SUBLIST-015) and deletes it again.
- **T7-SET-12:** a Syslog level of the PublicationList can be switched (REQ-TOP-027, SHOULD). The Mode is set back afterwards.

## Defects found (test-first, fixed)

All in D7 or the sim, found by the fixtures before the demo run.

- **Sim:** one DataSetWriterId for Status Good and Bad violated REQ-MSG-021 (a DataSetWriterId describes one DataSet). Fixed with one writer per Source and level (see above).
- **D7 stimuli were invalid** (strict validation rejected them):
  - Set Config of an unknown object → now `{"d7":{"d7Unknown":{"Value":"D7"}}}` with an unknown Filter;
  - Set Data → `{"D7":1}`;
  - Set Metadata → a complete DataSetMetaDataType with empty lists (`unknownMeta`).
- **D7 sent destructive RefDes requests without a known state** (under the `T7-GET-01/reply-to` fault, Get ReferenceDesignation is not correlatable). SET-09 and SET-03 now send nothing destructive and skip.
- **D7 left subscriptions behind** when a creation got no Status event. It now deletes every entry it may have created (not after Status Bad).
- **Skip reasons** distinguish "the CUT does not answer Get <resource> without Source" from "the CUT has no …".

Found by the code review of the uncommitted change (after the demo run), fixed test-first:
- **Masked Config at level 1:** D7 wrote the mask back although REQ-RES-CONFIG-025 is only SHOULD at level 1. A CUT that stores the mask would lose its secret, and the restore check cannot see it (the mask is published either way). Test `TestSimMaskLevel1` (red: 5 Set Config of the masked DataSet, CONFIG-025 pass) → fix A-188.
- **ReferenceDesignation deleted without a confirmed restore:** SET-09 ignored the result of the write-back Set; SET-04 and the Del stimulus of SET-03 sent no Set before the Del. A CUT that rejects Set but accepts Del lost its object. New conforming fault `T7-SET-09/set-rejected` (red: both objects deleted and not restored) → fix A-189.
- **Interrupted run:** an error during the write tests returned no restore result, so neither the report nor the CLI warned that the CUT may be modified. Test `TestSimInterruptedWrite` (red: no restore result) → fix A-190.

## Agent decisions (G-3.4 b, for information: REVIEW A-176 … A-190)

All in ADR-0025 amendment C-064 and DESIGN.md §3.3/§10 "As built (C-064)".

- **A-176** Increment 3 not split; SET-10 stays in increment 6.
- **A-177** The restore model:
  - Snapshot = Get without Source of Config, PublicationList, ReferenceDesignation and SubscriptionList, before the first and after the last write test.
  - Data is excluded (its values change by themselves), and the disk of the CUT is not compared.
- **A-178** The restore result is reported, not judged: report key `restore` (report version stays 1), a text line, and a stderr warning with the changed lines.
- **A-179** Writes are write-backs:
  - a Set sends what the CUT published;
  - Config is written back as the full DataSet including the mask;
  - Data is written only where it is offered (listed Set subscription).
- **A-180** Destructive requests are bounded:
  - Only SubscriptionList entries D7 created are deleted (also after a creation without a Status event, not after Status Bad).
  - A ReferenceDesignation is deleted only with a known state and a confirmed write-back (A-189), and restored with Set.
  - `NONE_0` entries get only a change that must be rejected; it is undone if it is accepted.
  - Changed PublicationList Modes are set back.
- **A-181** "Nothing published" (REQ-BUS-007) means nothing until the Status event plus the grace time.
- **A-182** SET-03 runs after the other write tests and reuses their reactions. Supported = any reaction with the `ReplyTo` except BadNotSupported.
- **A-183** SET-01 judges REQ-RES-SUBLIST-016/CMP-016 after the catalog note: Good → checked; BadNotWritable/BadNotSupported → violation; other outcomes → skip.
- **A-184** Stimuli:
  - unknown objects with the prefix `d7`/`D7`;
  - the DataSetWriterId of a created ReferenceDesignation is taken from the PublicationList entry (else 10);
  - SET-05 sends one deliberately invalid Number (tester violation REQ-RES-CONFIG-007).
- **A-185** The Status event is the Event of the category Status whose `ReplyTo` is the MessageId of the request. Its level comes from the severity bits of the StatusCode. Its Source is the Source of the request, or the AppId for an asset the entity neither is nor represents (SF-108).
- **A-186** Sim:
  - write side;
  - `Changed()`;
  - one Status DataSetWriterId per Source and level (the Get-path Bad event moves from 623 to 625);
  - content additions;
  - only the application's Data is writable.
- **A-187** The fixture contract checks the restore: D7 against `sim.Changed()`; restored without a fault; `Changed()` empty after every run.
- **A-188** A Config DataSet with a masked sensitive value is written back only where REQ-RES-CONFIG-025 is MUST (level 2 and 3). At level 1 D7 does not write it (SET-01, SET-05) and skips CONFIG-025 for it. The restore note says that sensitive values cannot be compared.
- **A-189** D7 deletes a ReferenceDesignation only after a write-back Set of it got Status Good. Otherwise SET-09 skips REFDES-010, SET-04 judges REQ-BUS-007 on its own SubscriptionList entry (or skips), and SET-03 skips the Del of that Source.
- **A-190** A run that ends during the write tests reports the restore as not checked with a note naming the test; `oec-check test` warns. D7 makes no recovery attempt after the error.
