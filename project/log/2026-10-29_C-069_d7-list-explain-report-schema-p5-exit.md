## Work

### 1. Report schema (`4ce2f57`)

- **Root package `conformance`** (`oec/conformance/conformance.go`, A-230): embeds `report.schema.json` and the fixture indexes `testdata/sim/index.yaml` and `testdata/captures/index.yaml`; `ValidateReport(doc)` validates a decoded report; loaders of both indexes (the probe/monitor tests now use them). `go:embed` cannot reach `testdata/` from a sub-package, and `internal/report` imports `probe`, so the sim tests in `probe` cannot use `report` – the root package imports no tool package.
- **`report.schema.json`** (JSON Schema 2020-12, `$id` `https://schemas.openindustry4.com/oec/tools/oec-check/report.schema.json`), report version 1 of `monitor` and `test` (A-231):
  - closed objects (`additionalProperties: false`) for the report, the participants, findings, tests, requests, restore, connections and announced components;
  - conditional keys: `mode` `test` requires `app` and `tester`; `replay` requires `capture` and has no `broker`; live and test require `broker`; `attachment` `proxy` requires `proxy_listen`, only then `connections`;
  - enums for verdicts, severities, the request labels and the proxy connection outcomes.
- **Validation in the gate**: the CLI tests (`--format json` on stdout and `--report json=` files of `monitor` and `test`), every capture replay at levels 1–3 (`TestMonitorReplayExitCodes`), every sim fixture run (`TestSimFixtures` and the single sim tests; the report document is assembled in the test with the keys of `report.Monitor`, because of the import cycle; the CLI tests cover the real `report.Monitor`).
- **`discovery` label** (A-232): the schema found that the Profile read of the discovery phase had an empty `test` label in `requests`; `internal/probe/probe.go` labels it `discovery` (test first: the schema validation of the sim fixtures failed before the fix).

### 2. `list`, `explain`, `report-schema` (`3636ea0`)

- **`internal/explain`**: a read-only view on the catalog, `spec.FS` (requirements and inventory sources) and the fixture indexes.
  - `List(filter)` – tests with mode, level, status, `needs`, REQs; filters `--mode`, `--level` (tests that run at that level), `--req`, `--needs` (`proxy|restart-hook|peer|none`), `--status`, and id patterns (`T7-SET-*`).
  - `Test(id)`/`TestFixtures` – a test with its REQs (keyword, level, MG/RIG source) and its sim and capture fixtures with the expected verdict of the index (positive fixtures as "pass or not applicable"; a sim fixture without the peer is not listed for a test that needs the peer).
  - `TestsOf`/`Manual`/`ReqFixtures`/`ValidateKinds` – for a REQ: the tests that check it, the `manual` reason of the catalog, the fixtures of those tests, and whether `validate` checks it (`schema`/`d7-validate`); the REQ text, sources and quotes come from `spec.FS`.
- **CLI**: `oec-check list [--format text|json] [filters] [patterns]`, `oec-check explain [--format text|json] <test|REQ>`, `oec-check report-schema` (prints the embedded schema); `version` also names the catalog baseline and the report version (A-233). Usage errors (unknown id, more than one id, unknown filter value) exit 2.
- **Catalog JSON tags** (`internal/catalog/catalog.go`) for `--format json`.
- Tests first: `internal/explain/explain_test.go` (`TestSource`, `TestIndex`), `cmd/oec-check/list_test.go` (`TestList`, `TestExplain`: text and JSON output, filters, exit codes; `TestReportSchemaCommand`: the printed schema equals the embedded file).
