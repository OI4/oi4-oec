## Work

### 1. The tests (`internal/probe`)

New files `resources.go` (GET-03, GET-04, the resource lists of the levels), `helpers.go` (GET-06, GET-07, GET-08 and the series/answer helpers), `adr.go` (ADR-02, ADR-03); `probe.go`/`session.go` extended (helper DataSetMessages Pagination/Query/Locale with the reserved DataSetWriterIds, `Oi4/#` for ADR-02, the judgement at the end of the run).

- **T7-GET-03:** every resource of the Profile answers Get without Source, with the Source of the application and with up to 5 Filters taken from the first answer (the answer to a Filter is the subset with that Filter). Every PublicationList entry (up to 50) of a requestable resource with a Mode other than `OFF_0` answers Get (SF-101). Get Metadata is sent for the Data the PublicationList announces. REQ-CMP-008, 019, 020, 035 … 037, 039, RES-CONFIG-017, RES-DATA-007, RES-META-002, RES-PUBLIST-020, 027, RES-REFDES-004, RES-SUBLIST-008.
- **T7-GET-04:** the application (REQ-CMP-024) and every subordinate Source (REQ-CMP-045, up to 20) answer Get with their Source for every resource of the level; at level 2 the recommended resources are REQ-CMP-010.
- **T7-GET-06:** Get MAM without PaginationRequest is the complete series (REQ-PAG-005). With `PerPage` 1 the pages 1, one beyond the end and 0 (all pages) are judged (REQ-PAG-002). Pagination by size cannot be stimulated (D7 does not control the content size); T7-MON-18 judges `MaxPacketSize` on every NetworkMessage.
- **T7-GET-07:** a Query `Parent` on Get ReferenceDesignation without Source returns the direct children (REQ-RES-REFDES-011/014) or – if not supported, optional at levels 1/2 – is ignored (REQ-QRY-003). An undefined query parameter is ignored (REQ-QRY-002). A Query on Get ReferenceDesignation/<AppId> is ignored (REQ-RES-REFDES-013), and so is a Query on Get MAM (REQ-QRY-001). The parent is the first one with fewer children than objects, so a supported and an ignored Query can be told apart.
- **T7-GET-08:** Get MAM and Get Config/<AppId> with the Locale `de-DE`: every LocalizedText of the answer is `de-DE`, `en-US` (default language) or the invariant locale (REQ-LOC-002).
- **T7-ADR-02:** D7 sends under `Oi4v2` only and listens to `Oi4/#` best effort. A message under `Oi4` with the MessageId of a request of D7 is an answer in the wrong version (REQ-TOP-004). Without any `Oi4` traffic the CUT supports one version and the REQ is skipped (its condition).
- **T7-ADR-03:** Get MAM with the exact Identification Link of each asset is answered on that Source with exactly that IL (REQ-IL-001, 013, TOP-018); a Get with an IL that differs in the case of one letter is not answered as the same asset (REQ-IL-015).

## Defects found (test-first, fixed)

- **Monitor, REQ-LIFE-003 false positive.** An answer to a Get with a Locale (MAM in German) differs from the Birth by design; the monitor compared it as a new Birth. The engine now records the MessageIds of Gets with a Locale and skips the comparison for their answers (`TestLocalizedMAM`).
- **Monitor, REQ-PAG-005 false positive.** For a Get with `Page` > 0 only the requested page is published (REQ-PAG-002); its `HasNext` true is not an unfinished series. The engine records the requested page per MessageId and judges such an answer as a single page (`TestRequestedPage`). The reviewed capture `pagination-broken.jsonl` relied on the wrong behaviour (see below).
- **T7-GET-06 crashed** (nil pointer) on an answer to page 0 without Pagination; now a violation.
- **T7-GET-07 judged REQ-RES-REFDES-013 wrong.** The first demo run failed REQ-RES-REFDES-013: D7 expected the object of the application as the answer to Get ReferenceDesignation/<AppId> with a Query. The demo has no ReferenceDesignation object and answers `[]` with and without the Query – conforming. "Ignored" means "answered like the same Get without it": D7 now compares with that Get. Without any object the Query REQs 011/014, QRY-002/003 are skipped (cannot be judged). New positive fixture `T7-GET-07/empty` (red before the fix). The SDK was not changed.
- **`Judge`** reported only `implemented` tests, so the new tests were invisible until the catalog was updated (expected behaviour; noted for the order of work).
