## Intent

PO input (chat, 2026-10-17):

- **SF-043 (a)–(d):** the proposed interpretations are accepted. Addition: the `ManufacturerUri` in the MAM shall correspond to the Identification Link of the asset; in case of doubt it is given without scheme and without third-level domain.
- **Review:** `oec/spec/requirements/view/il.md` is fine.
- **REQ-TOP-007** ("a device that communicates directly with the Message Bus uses the ServiceType `OTConnector`") is withdrawn, because the guideline defines no such rule for the other ServiceTypes. This changes SF-042 (d).
- **Guideline:** implement SF-040 and SF-042, and SF-043 (a)–(d) as well.

The PO did not list SF-041. Asked once – the PO was not available. Assumption: SF-041 stays decided but is not implemented in the guideline in this cycle. Where SF-040 and SF-041 touch the same example (MG B1.1.8), only the SF-040 part (`%20`) is changed.

Interpretation of the `ManufacturerUri` addition (agent):

- The `ManufacturerUri` of the MAM should correspond to the host of the asset's Identification Link: same domain, lower case, without scheme, port and path. This makes the rule a SHOULD.
- If in doubt, it is `<manufacturer>.<tld>`, i.e. without scheme and third-level domain. Proposal (c) remains: subdomains are allowed and a leading `www.` is excluded.

The planned area cycle MSG + ACT moves to C-021. Later P1 cycles shift by one, as in C-015, C-017 and C-019.
