## Work

### 1. Oracle ↔ schema crosscheck (`fcd7d2c`, `504efc4`)

P2 exit criterion 5 says the oracle checks every rule that a schema enforces. Until now this was only implied by the vectors (lint: `violates` = oracle; harness: schema REQs = `violates` or the expectation list). The probes (P-01 … P-128) and the generic-schema cases were never run through the oracle.

- `schematest` writes the topic, mode, object, schema file and reported REQs of every case into `oec/schema/dist/cases.json` (`fcd7d2c`).
- New command `spectool crosscheck` (`504efc4`) runs the oracle on every case and compares:
  - an entry schema rejects with the REQ set S → the oracle rejects with a superset of S;
  - the generic `message.schema.json` rejects → the oracle rejects (the REQ sets differ by design: without a topic the generic schema reports other REQs);
  - the schema accepts → the oracle reports only REQs with `d7-validate` (rule layer).
- First run: 5 disagreements. Four were generic-schema cases (rule 2 above was added for them). One was a real **oracle gap**: probe P-16 (`ReplyTo` `1639693510094-abc`) is rejected by `$defs/ReplyTo` of `envelope.schema.json`, but the oracle accepted it, because it only checked the `<timestamp>-<text>` shape.

Result: 634 cases; 566 agree (14 where the oracle reports further REQs, 4 generic-schema rejections with other REQs), 68 schema-valid cases with rule-layer REQs, **0 disagreements**.

### 2. Oracle fix: ReplyTo sender (`111cad9`)

The oracle now requires the sender part of a non-empty ReplyTo to be a PublisherId `<ServiceType>/<IL>` (REQ-MSG-015; MG 8.2.1: a MessageId is `<timestamp>-<PublisherId>`), as the schema does. New unit test "reply to sender". No vector changes (no reviewed vector had such a ReplyTo).

### 4. Reclassification: 7 REQs lose `schema` (`358771c`, `draft`)

| REQ | Verification before → after | Why no schema |
|---|---|---|
| REQ-LIFE-003 | `schema`, `d7-validate`, `d7-monitor` → `d7-validate`, `d7-monitor` | the Birth role is not visible in one message (rule R-6 with `--role`) |
| REQ-LIFE-007 | `schema`, `d7-validate`, `d7-test` → `d7-validate`, `d7-test` | Close role (R-6) |
| REQ-LIFE-009 | `schema`, `d7-validate`, `d7-test` → `d7-validate`, `d7-test` | Will role (R-6) |
| REQ-MSG-023 | `schema`, `d7-validate` → `d7-validate` | DataSetWriterName = Source of the topic (R-2) |

| REQ-RES-REFDES-013 | `schema`, `d7-validate`, `d7-test` → `d7-validate`, `d7-test` | `Query` only without Source in the topic (R-2) |

Each REQ got a note "Reclassified in C-041 (-schema, …)" and status `draft` (changed reviewed items, PO review **R-1**).
