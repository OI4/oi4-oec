### Test catalog (`oec/conformance/catalog/`, `483c227`)

The catalog is data, not code: `d7.yaml` and `d8.yaml` are embedded with `go:embed` and loaded strictly.

**Design choices:**
- **Grouping by stimulus, not by area.** A test is something the tool does once. One test checks all REQs that the same stimulus or observation decides. Example: T7-SET-01 "Set and Del are answered with Status events and publications" covers REQs from CMP, BUS and MSG.
- **Level = the first level at which one of the test's REQs applies.** Each REQ inside a test is judged at its own obligation for the declared level. A first draft used the maximum level of the REQs. That would have skipped L1-MUST REQs at level 1 (52 REQs, e.g. the correctness of `Get` answers when a CUT answers at all), so the rule was changed to the minimum before committing. The gate enforces equality, so the field cannot drift.
- **`needs`.** Tests that need more than a bus client declare it:
  - D7: `proxy`, `restart-hook`, `peer`;
  - D8: `docker`, `host-access`, `credentials-2`.
- **`manual:`** lists live REQs that a black-box tool cannot observe, each with a reason:
  - REQ-CMP-011 (rule for the tool: default level 3);
  - REQ-LIFE-011/012/013 (subscriber-side behavior);
  - REQ-CMP-012 (D8, the same rule for containers).

**Result:**

| Catalog | Tests | By mode | `needs` | `manual:` |
|---|---|---|---|---|
| D7 | 54 | 19 monitor, 35 test | proxy 7, restart-hook 2, peer 1 | 4 |
| D8 | 17 | image 4, run 3, container 3, host 4, bus 3 | docker 7, host-access 4, credentials-2 1 | 1 |

All 47 `d7-monitor`, 119 `d7-test` and 50 `d8` REQs are covered.

**Gate** – `catalog_test.go` checks against `spec.FS`:
- tool name and baseline;
- id format and uniqueness;
- status;
- mode ↔ verification kind;
- REQ existence and non-deprecation;
- level rule;
- `needs` vocabulary;
- manual entries;
- full coverage.

The gate was mutation-checked: a wrong REQ, a wrong level and a dropped REQ each fail with a precise message.

`independence_test.go` fails if `go.mod` references an `oec/` module other than `spec`/`schema` (Q-009).

Both tests run in `oec/check.sh` via the existing `go test ./...` of `oec/conformance`. This makes P3 exit criterion 4 a standing gate: a re-baseline that adds or reclassifies a REQ fails until the catalog follows.

### Design (`oec/conformance/DESIGN.md`) and ADR-0025 (`870e15b`)

**Commands.**
- D7: `validate` (unchanged), `monitor` (QoS-1 subscription to `Oi4v2/#`; `--record`/`--replay` capture in JSONL as a superset of the validate message file), `test` (default `--level 3` per REQ-CMP-011; restores what it changes; requires `--app`), `list`, `explain`, `version`.
- D8: `image`, `run`, `container`, `host`, `bus`. These names replace the ROADMAP working names `inspect-*`; the ROADMAP P5b note is updated.

**Attachment modes:**
- bus client (default);
- **proxy:** D7 is the CUT's TLS endpoint and relays to the broker. It is the only broker-independent way to see CONNECT, Will, TLS version, certificate checks and recovery;
- restart hook;
- peer.

**Verdict model.**
- Outcomes: pass/fail/warn/info/skip/manual.
- Severity from the REQ obligation at the declared level.

**Exit codes.** 0–3 as in `validate`, plus **4 = inconclusive** (a MUST test was skipped); `--allow-skip`.

**Reports.** Text, JSON (`report.schema.json`) and JUnit XML, several at once.

**Config.** A config file, overridable by flags; `--bus-storage DIR` reads the RIG Message Bus storage.

**Libraries.**
- `eclipse/paho.mqtt.golang` v1.5.x, taken under EDL-1.0 (BSD-3); its `packets` codec also serves the proxy.
- `google/go-containerregistry` (Apache-2.0).
- An own minimal Engine API client and SBOM reader.
- `mochi-mqtt/server` (MIT) in tests only.
- Rejected:
  - `paho.golang` (MQTT 5 only);
  - the Docker SDK (size);
  - `spdx/tools-golang` (no stable release, license NOASSERTION).
- Facts checked on 2026-10-26 (pkg.go.dev, GitHub).

**Self-test.** A simulated CUT (`internal/sim`) with one fault per catalog test; positive and negative fixtures become the P5 exit evidence.

**Distribution.**
- `CGO_ENABLED=0` cross builds for windows/darwin/linux × amd64/arm64; ARMv7 best effort.
- A `FROM scratch` multi-arch image.
- Release tooling and signing are decided in P9 with Q-011.

### Questions (`24243c6`)

- **Q-028:** is proxy mode required for a full level claim? Recommended: yes; without the proxy the run is inconclusive.
- **Q-029:** tester identity. Recommended: not announced by default; `--announce` optional.
- **Q-030:** exit code 4 "inconclusive". Recommended: yes.

### No spec findings

Writing the catalog required reading every `d7-test`/`d7-monitor`/`d8` statement. No new unclarity came up. The subscriber-side REQs LIFE-011…013 are not ambiguous; they are not observable from outside, so they are `manual`.
