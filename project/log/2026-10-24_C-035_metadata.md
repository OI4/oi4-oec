### 4. ADR-0019 amendment C-035 (agent proposals, PO review)

1. **§8 bare MetaData → `ResourceMetaData`.** ADR-0019 §8 routes bare vectors to `#/$defs/DataSetMetaData`. But the oracle also checks the A2 DataSetClassId of a predefined resource (REQ-MSG-012/010), so the exact REQ comparison needs a schema that sees it: `ResourceMetaData` = `DataSetMetaData` + one `if Name = <resource> then {REQ-MSG-012 required DataSetClassId; REQ-MSG-010 const <A2 id>}` per resource with a predefined id. `DataSetMetaData` stays the generic schema (A).
2. **§5 R-3** also covers name uniqueness by key (REQ-MSG-038/043/044).
3. **§5 new rule R-6 – declared role** (§5 below).
4. **§9 applied** to REQ-LIFE-003/007/009.

### 5. LIFE roles (Q-020 (a), `ffd45ac`)

- **Vector field `role`** (`birth`/`close`/`will`; `vectors.schema.json`, `Vector.Role`): only for a message with a topic (not for a bare object).
- **Oracle `CheckRole`** (`internal/payload/role.go`), applied by lint in addition to `CheckMode`:
  - Birth: Pub MAM with exactly one DataSetMessage whose `ProductInstanceUri` is the AppId → REQ-LIFE-003;
  - Close: Pub Health with exactly one DataSetMessage, `Health` `NORMAL_0`, `HealthScore` 0 → REQ-LIFE-007;
  - Will: the same with `FAILURE_1` → REQ-LIFE-009.
- **Not part of the role check:** the topic rules of the roles (Source = AppId: REQ-LIFE-002 `d7-monitor`, REQ-LIFE-006/008 `d7-test`) and the DataSetWriterId shared with the regular messages (multi-message, R-5). The PO decision named REQ-LIFE-003/007/009 only; widening it to the topic REQs is a question for the PO (D-3 in `REVIEW.md`).
  - Consequence for the vectors: every negative must violate only the content REQ. A Birth about another asset (Source ≠ AppId) would also violate REQ-LIFE-002, which lint cannot list in `violates` (the oracle does not report it). Such cases are covered by unit tests (`role_test.go`), not by vectors. Since REQ-RES-MAM-016 (ProductInstanceUri = DataSetWriterName) and R-2 (DataSetWriterName = Source) already hold for every Pub MAM, "ProductInstanceUri = AppId" of a valid Pub MAM is the same as "Source = AppId".
- **Lint consistency:** a valid vector with a role names the role REQ in `reqs`; a vector that names REQ-LIFE-003/007/009 in `reqs`/`violates` has the matching role.
- **Schema side:** the role is not in the message, so the schemas accept the role negatives; the expectation list partitions them (schema `[]`, rule REQ-LIFE-xxx, R-6).
- D7 `validate --role` comes with D7 in C-039.
