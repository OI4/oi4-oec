## Goal

Increment 3 as handed over: a generated workflow `micro.yml` for the micro SDK – host checks on Linux amd64/arm64 and Windows, the ESP-IDF builds `esp32`, `esp32s3` and `qemu` in the Espressif container pinned by digest with the QEMU D7 run at levels 1/2/3, the Arduino builds with a pinned `arduino-cli` 1.5.1 on Arduino-ESP32 3.3.x and 4.0 (C3/C6 best effort); caches for downloads only, no artifacts with firmware secrets. The logic in scripts under `oec/ci/`; everything verified locally, the hosted runs follow in the exit run C-111 (C-105 D-2 (b)).

## What was done

### 1. `micro.yml` (ADR-0032 amendment C-106, A-576 … A-581)

Generated by `oec/ci/pipelines` (`Micro()`; test first: `TestMicro`, `TestRunners` with `micro/host`), the policy of C-104 unchanged (only `actions/*` pinned by SHA, `contents: read`, concurrency per ref, timeouts). Triggers as `sdk.yml`: push to `main`, pull requests, `workflow_dispatch`. Three jobs, no artifacts (a firmware artifact would be a release channel, Q-011):

| Job | Runners | Script | What it does |
|---|---|---|---|
| `host` | `ubuntu-24.04`, `ubuntu-24.04-arm`, `windows-2025` | `micro-host.sh` | Linux: `sdk/micro/check.sh` with the runner's GCC (`CC=gcc`, `OECM_ANALYZER=clang`), incl. D7 levels 1–3 through `oecm-host` (A-577). Windows: the portable part with MinGW gcc (A-578) |
| `esp-idf` | `ubuntu-24.04` | `micro-esp-idf.sh` | builds `oec-check`, the `cmd/oecm-qemu` test binary and `go-testbroker` on the host; `idf.py` builds of `esp32`, `esp32s3` and `qemu` in `espressif/idf:v6.1@sha256:…`, then D7 `--level 1/2/3` against the `qemu` firmware (A-579) |
| `arduino` | `ubuntu-24.04` × core `3.3`, `4.0` | `micro-arduino.sh` | `arduino-cli` 1.5.1 (SHA-256 of `versions.sh`), the library from `arduino/package.sh`, `Sensor` on ESP32/ESP32-S3 and `M5Stack` on M5Core2/M5CoreS3 required (an own warning fails), ESP32-C3/C6 best effort (annotation) (A-580) |

Pins in `oec/ci/versions.sh`: `espressif_idf_image` (index digest, amd64 + arm64), `arduino_cli_version` 1.5.1 with the SHA-256 for linux amd64/arm64 and darwin arm64, `arduino_esp32_3_3=3.3.12`, `arduino_esp32_4_0=4.0.0-RC1`, `m5unified_version=0.2.29`, `m5gfx_version=0.2.36`.

**Arduino-ESP32 4.0:** 4.0.0 final is not released (2026-11-22); the job builds the newest release candidate **4.0.0-RC1**, pinned explicitly – `arduino-cli core list` shows 4.0.0-alpha1 as "latest", because semver sorts `RC1` before `alpha1`. The pin changes when 4.0.0 is out (to re-check in C-111; ROADMAP P9 exit criterion 3 names "4.0 final").

**Caches (A-581):** only the crates of `go-testbroker` (`~/.cargo/registry`, key prefix `oec-micro-`, apart from `oec-sdk-` and the gate's tool cache). Not cached: the Arduino cores (≈ 4 GB download each) and the Espressif image (≈ 8.5 GB) – they would exceed the 10 GB cache of the repository and evict the gate's caches. `micro-arduino.sh` deletes the core downloads (`staging`) after the install.

### 2. `OECM_ANALYZER` (ADR-0030 amendment C-106, A-577)

`sdk/micro/check.sh` takes an optional `OECM_ANALYZER` (default `CC`) for the `--analyze` step, so `micro.yml` builds with GCC and still analyzes with clang. The gate is unchanged (clang).

### 3. Windows (A-578)

The MinGW gcc of the runner (the cgo compiler of the Go SDK since A-563), amd64. **Not on Windows** (Unix only): the D7 runs of the host runner (`internal/d7run` uses `/bin/sh` restart hooks and POSIX signals – the A-550 area, not changed), ASan/UBSan (MinGW has none), `clang --analyze` and the symbol allowlist (properties of the sources, checked on Linux). **On Windows:** gofmt, vet, `go test -race` of `./mqtt` and `./cmd/oecm-vecgen`, all commands built with cgo, `oecm-vecgen -check`, CMake (`MinGW Makefiles`, no sanitizers) and ctest, GCC `-O2` with the warnings of the gate (LLP64), `oec-check validate` of the emitted payloads, `hello_device`, `arduino/package.sh`, the headers as C++17. `micro-host.sh` converts its temporary directory with `cygpath -m`, so bash and the native programs see the same path.
