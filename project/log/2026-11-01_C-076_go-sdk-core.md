## Work

### 1. Spike finding and start errors – `oec-ffi` (`ff048d3`, test first)

- **Spike finding explained, no defect.** A MAM subscription of an app started with `oec_app_start` receives the Birth of a peer that connects later and its own MAM as answer of a `Get`, but never its own Birth: the runtime subscribes after the Birth (the Birth is the first message, REQ-LIFE-015) and MAM is not retained. In the spike no peer connected within the 15 s. New C test `tests/c/abi.c` `lifecycle` shows all three cases.
- **Defect found: start errors of `oec_app_start` were not observable** (ADR-0021 §8 said so, A-150 recorded it for information): with an unusable CA the thread ended, and C saw only "never online". Fixed additively: **`oec_app_wait(app, timeout_ms)`** returns the result of the run (`OEC_OK` after shutdown, the start error with `oec_last_error`, `OEC_ERR_TIMEOUT` while it runs) and **`oec_app_state(app, &state)`** the connection state. C tests first (`wait`, `state`, start error with a garbage CA, timeout 0, `OEC_WAIT_FOREVER`, invalid state without start), then the code; ABI version stays 1, header 43 → 45 functions, no existing test changed. ADR-0021 amendment C-076.
- **Why Go needs `oec_app_wait`:** `oec_app_run` installs SIGINT/SIGTERM handlers (tokio) without `SA_ONSTACK`; the Go runtime requires that flag of non-Go handlers ("Go programs that use cgo", `os/signal`), and the handlers would take the signals from the program. `App.Run(ctx)` uses `oec_app_start` + `oec_app_wait`.

### 2. Go package `oec/sdk/go`

- `go.mod`: `github.com/OI4/oec/sdk/go`, `go 1.26.0`, toolchain `go1.27.3` (as `oec/conformance`); no `require`.
- `link.go` – default `#cgo` flags per OS (ADR-0027 amendment C-076 §3), build tag `oec_external` for own flags; `doc.go` – package documentation (build, hello world, threading, errors).
- `errors.go` – `Status` (= `oec_status`), `*Error{Status, Message, StatusCode}`, `Is` by status, sentinels `ErrInvalidArgument` … `ErrInternal`; `call` locks the OS thread for the C call and the read of `oec_last_error`/`oec_last_status_code`.
- `types.go` – `Level`, `ServiceType` (+1, zero = any), `Health`, `NoScore`, `SyslogLevel` (+1, zero = default), `ConnectionState`, `StatusCode` with names.
- `app.go` – `Version`, `ABIVersion` check at the first `New`, `Product`, `Broker`, `Options`, `New`, `App.Start`/`Run`/`Shutdown`/`Close`/`State`/`This`/`Syslog`, `Asset.SetHealth`. `Run` returns nil after a stop by `ctx`, `Shutdown` or `Close` and the start error otherwise; an RW lock keeps calls off a released handle; no finalizer.
- `cmd/oec-buildlib` – Go program instead of a shell script (A-314): `cargo build --release -p oec-ffi` (`-target`, `-profile`), target directory from `cargo metadata`, Rust triple → `GOOS_GOARCH`, atomic copy to `lib/<goos>_<goarch>/liboec_ffi.a` (git-ignored, ~30 MB).
- `examples/hello` – Level 1 Utility "Hello OEC Go" (`HELLO-GO-1`), `OEC_ROOT` = root of the container storage, `signal.NotifyContext`.
- `README.md` – build, link flags and their override, hello world, rules (threads, signals, lifetime, errors, callbacks), tests.

### 3. Test harness: Rust helper program `go-testbroker` (A-315)

- Decision (ADR-0027 §9 left it open): a **Rust helper program the Go tests start**, not a Rust test that builds Go programs. Reasons: the Go tests stay plain `go test -race`; each test starts its own broker; tests inject messages and connection drops; failures show as Go test failures with Go names.
- `oec-ffi/tests/go/testbroker.rs`, registered as Cargo example `go-testbroker` (`test = false`); it includes the shared test broker of `oec/tests/testbroker` (`#[path]`, routing variant, PKI per start written to the directory given as argument). JSON lines on stdout: first `{port, ca, client_cert, client_key}`, then one line per observed packet (`tls`, `connect` with client id/user/Will topic, `publish` with topic/payload/retain, `subscribe`/`unsubscribe` with filters, `disconnect`, `closed`); stdin `{"cmd":"send"|"drop", …}`; ends when stdin closes. clippy pedantic and fmt clean; no new dependency.
- `harness_test.go` (start, expect with timeout, inject, temporary container storage), `app_test.go` (version/ABI, errors and sentinels, rejected options, start error from `Run` and `Close`, lifecycle Birth → Health → Syslog → Close message → DISCONNECT, `Run` stopped by `ctx`, `Shutdown` before `Run`, concurrent `Close`, explicit broker with credentials), `examples_test.go` (build and run `hello` with SIGTERM: Close message, DISCONNECT, exit 0).
- Without the helper the tests skip; `OEC_GO_REQUIRE_BROKER=1` (set by the gate) makes that a failure.

### 4. D7 `test` at `level1` against `hello` in the gate (A-316)

- A broker without Docker suffices, so the run is in the gate (ADR-0027 §9): `d7_test.go` builds `hello`, gives it a container storage whose `broker.json` points to the TLS proxy of D7 (proxy CA generated with the Go standard library), and runs `oec-check test --level 1 --timeout 3s --proxy … --stop-cmd … --start-cmd … --restart-wait 15s --peer --announce --report json=…` against the go-testbroker. `oec-check` is built from `oec/conformance` into a temporary directory and started by exec – no code import between the modules (ADR-0006).
- Assertions: exit 0, no `fail`, and `pass` for T7-MON-01 … 06, T7-CON-01 … 04 and T7-LIFE-01 … 04.
- Result (also in the gate): **PASS, exit 0 – 21 pass, 5 warn, 29 skip, 0 fail**. Warnings T7-GET-05, T7-SET-01, -02, -06, -07: all SHOULD at Level 1 (no `Get`/`Set` answers, no Status events). Pass: T7-MON-01 … 06, 08, 10, 11, 12, 16, 19, T7-CON-01 … 04, T7-LIFE-01 … 04, T7-ADR-03.
- Duration: 7.5 min with the default timeout 10 s, 3m50s with `--timeout 3s`, **2 min** with `--restart-wait 15s` as well: the restart phase of D7 waits for the answer to a `Get Health`, which a Level 1 app never gives, so it always ran into the 2-min default.
- Observation (no finding): at Level 1 the Rust SDK subscribes to nothing (`oec-core/src/provider.rs` `subscriptions()`, "none at Level 1"); D7 sends 54 requests and gets no answer. Conformant: `Get` is required from Level 2 (REQ-CMP), `Set`/`Del` answers and Status events are SHOULD at Level 1.
