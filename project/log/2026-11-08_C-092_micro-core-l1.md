# C-092 – P4b start: micro SDK core, Messaging Level 1

- Date: 2026-11-08
- Phase: P4b – Micro SDK (D9), increment 1 of 6 (ADR-0030 §10)
- PO input: C-091 addendum 1 – "P7 schließen, dann P4b – Micro SDK (D9). Das Micro SDK soll möglichst in einer Session durchgebaut werden." Ask only when something really does not work, is unclear or needs a guideline change.
- Baseline: guideline `52d8470` (unchanged since C-078), SF-001 … 117 resolved, next SF-118.

## Goal

Start P4b: the implementation ADR, the cycle cut and the first increment – the portable C17 core for Messaging Level 1, tested on the host against the shared vectors and judged by D7.

## What was done

1. **ADR-0030** (`accepted (agent, G-3.4 b)`, A-429): layout of `oec/sdk/micro/`, core rules, CMake host build, generated vector header, payload check by D7 `validate`, static analysis and fuzzing (from L2), the Go cgo host runner for D7 (C-093), ESP-IDF v6.1 + QEMU opt-in, DataSetWriterIds, cycle cut C-092 … C-097.
2. **Header** `oec/sdk/micro/include/oecm.h` (moved from `sketch/include/`, the folder `sketch/` is removed): ADR-0022 amendment C-092 (A-430 … A-434) – `global_asset_id`, `NULL` defaults, derived ClientId, init and timer rules, measured sizes.
3. **Core** (`src/`, 3 files, ~880 lines):
   - `oecm_il.c` – Identification Link check (empty, too-long, forbidden-character, empty-authority, uppercase-authority) in the order of `oec-core` `il.rs`, canonical base64url encode/decode, dnp-encoding, ManufacturerUri rule, Oi4Identifier (lower-cased ManufacturerUri, `nd` for empty elements), UTF-8 validation;
   - `oecm_buf.c` – bounded output buffer (`full` flag, never writes past the capacity), integers, JSON strings;
   - `oecm_device.c` – topics, NetworkMessage, MAM and Health, the MessageId generator, the lifecycle (IDLE, CONNECTING, CONNECTED, BACKOFF, STOPPED), static assertions on size and alignment.
4. **Tests** (`tests/`, Unity v2.7.0 vendored unchanged under `third_party/unity/`, MIT, ADR-0024):
   - `test_il.c` (7 tests): all 29 IL vectors (check, encode, decode, violation codes in order), 13 Oi4Identifier vectors, 15 dnp vectors, canonical base64url, bounded decode of a too-long element, UTF-8, ManufacturerUri;
   - `test_json.c` (5): overflow never writes past the capacity, integers incl. `INT64_MIN`/`UINT64_MAX`, JSON escaping, base64url lengths, dnp;
   - `test_device.c` (18) with the recording PAL `fake_pal.c`: Birth then Health after connect, Will on the Health topic, MessageId counter while the clock stands, heartbeat at exactly 60 s, Health only on change, `set_health` arguments, Birth after a `FAILURE`/0 recovery (not after `FAILURE` with a score), Close then DISCONNECT, restart, backoff 1/2/4/8/16/30/30/30 s, connect timeout 30 s, failed publication stays due, wall clock check, derived and given ClientId (FNV-1a reference values), given IL with all optional MAM elements, every `oecm_init` error, Birth trial encoding, Level 1 ignores messages.
   - Vector header `tests/vectors_gen.h` generated by `host/cmd/oecm-vecgen` (Go, standard library) from `oec/spec/export/vectors`; `-check` in the gate.
5. **Payload check:** `tests/emit.c` runs two lifecycles (built Oi4Identifier with a non-ASCII model and `/`/`#` in product code and serial number; given IL with `Description`, `GlobalAssetId`, `HardwareRevision`, `RevisionCounter` 7, service type `Utility`) and writes 10 messages with roles `will`, `birth`, `close`; **D7 `oec-check validate`: 10 messages, 0 invalid**. A deliberately invalid message is rejected (exit 1), so the check is live.
6. **`oec/sdk/micro/check.sh`** = gate step 9 (`oec/check.sh`, header comment updated); `oec/sdk/check.sh` no longer compiles the sketch. Runtime about 6 s.
7. `oec/sdk/micro/README.md`, `examples/host/hello_device.c` (the sketch example, now linked and run).

## Agent decisions (G-3.4 b)

- **A-429 ADR-0030:** implementation of D9 as above; cycle cut C-092 (core L1), C-093 (Go host runner, D7 L1 in the gate), C-094 (L2), C-095 (L3), C-096 (ESP-IDF port, QEMU, footprint), C-097 (Arduino, M5Stack, docs page, exit). Without a connected board in this session the hardware run becomes a D-x at the P4b exit; QEMU is the evidence for the port.
- **A-430 Header additions:** `oecm_mam.global_asset_id` (REQ-RES-MAM-023, optional; appended, so the sketch's field order stays); `NULL` hardware/software revision → `"undefined"`, other `NULL` texts → `""`; derived ClientId `oec` + FNV-1a 64 hex of the IL (19 characters, below the 23 of MQTT 3.1.1).
- **A-431 `oecm_init`/`oecm_start`:** full validation at init (UTF-8, ManufacturerUri, IL or Oi4Identifier, `revision_counter ≥ -1`, Level 1 PAL functions); a trial Birth with the longest MessageId (`OECM_E_NOSPACE`); Level 2/3 return `OECM_E_LEVEL` until delivered; `oecm_start` refuses a wall clock before 2020-01-01 (`OECM_E_STATE`), because a MessageId with a wrong time is not globally unique (REQ-MSG-008).
- **A-432 Timers and Health:** reconnect backoff 1 s doubling to 30 s, connect timeout 30 s, poll interval ≤ 1000 ms; a failed publication stays due; `NORMAL`/0 is reserved for the Close; Birth again after an own `FAILURE`/0 (REQ-LIFE-017) – as `oec-core`.
- **A-433 Sizes:** `OECM_DEVICE_SIZE` 1024 (368 used at L1; L2/L3 state to come – the constant is an ABI constant, a later growth is a minor version per ADR-0022), `OECM_TX_MIN` 2048 (every Health/Will/Close fits for every valid IL; the Birth is checked at init).
- **A-434 Message shape:** as `oec-core`: DataSetWriterId MAM 10, Health 11; DataSetWriterName the IL; empty `WriterGroupName` and `ReplyTo`; no Timestamp, SequenceNumber or DataSetMessage MessageType.
- **A-435 Gate step 9:** `oec/sdk/micro/check.sh` – Go host module (gofmt, vet, test), `oecm-vecgen -check`, CMake build + ctest under ASan/UBSan, `clang --analyze`, symbol allowlist (`memcmp memcpy memmove memset strchr strlen`; `strchr` added to ADR-0030 §2 for the IL character set), GCC 14/15 if installed, emitter + D7 `validate`, the host example. Needs `cmake` (installed: 4.0.3).
- **A-436 Vector header instead of a JSON reader in the tests:** `oecm-vecgen` writes C literals with octal escapes (no trigraphs: `?` is escaped), `NULL` for absent fields; the test vectors stay the single source (G-1.4).
- **A-437 Toolchain outside the workspace (opt-in, C-096):** ESP-IDF v6.1 in `~/esp/esp-idf-v6.1` (`install.sh esp32,esp32s3`, tools in `~/.espressif`) and Espressif QEMU `esp_develop_9.2.2_20260417` (`idf_tools.py install qemu-xtensa`). Nothing of it is in the repository or the gate.
- **A-438 Sketch removed:** `oec/sdk/micro/sketch/` is gone (header and example moved with `git mv`, the sketch README replaced by `oec/sdk/micro/README.md`); `oec/sdk/check.sh` and the header of `oec/check.sh` say so. ADR-0022's context still names the sketch path as history.
