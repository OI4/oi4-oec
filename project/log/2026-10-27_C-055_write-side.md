## Cycle cut (agent decision G-3.4 b, A-87)

**Increment 7 is split into 7a, 7b and 7c.**
- **7a (this cycle):**
  - the request path for `Set`/`Del`;
  - Status events;
  - `BadNotFound` for requests to an unknown Source;
  - `Set PublicationList` with persistence;
  - `Set Data` with `DataSet::on_set`.

  These parts share one mechanism: a request is checked, answered with a Status event and correlated with `ReplyTo`. They are one review topic. Delivered size: about 1500 lines of source and 1330 lines of tests.
- **7b (next):** the Config resource:
  - `ConfigDef`/`ConfigHandle`/`on_set`;
  - `Get`/`Set Config`;
  - partial updates with mandatory elements;
  - masking of sensitive values (GL-ADR-021);
  - secrets under `/run/secrets/oi4` (GL-ADR-022);
  - persistence.

  It is its own security-relevant topic and reuses the write path of 7a unchanged. Together with 7a it would have doubled the cycle.
- **7c:** ReferenceDesignation (`Get`/`Set`/`Del`, `Asset::on_reference_designation` of the sketch), the Syslog bridge of the application (`log` → `Event/<Source>/Syslog/<Level>`, `AppBuilder::syslog`) and Generic events (`Asset::emit_event`, `CAT_GENERIC_99`). Each is small and uses the Status/Event writer of 7a, so they come after the Config path.
- **SubscriptionList → increment 8.** It lists the subscriptions of the consumer (MG 8.3.9: "actual subscriptions"), so it belongs with the consumer side. Until then a `Set`/`Del SubscriptionList` is answered with `BadNotFound`. SF-107 (below) may add entries for writable DataSets there.
- **Order 7a → 7b → 7c → 8 → 10.** 8 needs the Event writer of 7a for its own `Set SubscriptionList` answers. 10 needs the complete API.

ROADMAP P4 is updated: 7a ✅ C-055, rows C-056 (plan) 7b and 7c, and the SubscriptionList moves to 8.

### 2. `oec`: `on_set`, runtime, persistence (`1e45d72`, `a32416d`)

- **`oec::data`:**
  - `SetData::{get, fields}`;
  - `DataSet::on_set(handler) -> Result<()>`, refused for a removed DataSet and at Level 1;

- **`AppHandle`:**
  - handler registry `set_handlers`;
  - `on_set_data` and `complete_set_data` run the handler **outside the registry lock** and map a panic to `BadInternalError`;

- `StatusCode::to_core` maps the public code to the core code.

  - identified by Resource/Source/Filter; Mode normalized before comparison;
  - unknown → `BadNotFound`; not decodable → `BadDecodingError`; a change the `Config` forbids or a read-only property → `BadNotWritable`; an invalid Precision → `BadInvalidArgument`;

## Spec findings

Two new findings, both missing definitions in the guideline (G-3.4 a), recorded in `oi4-oec-documentation/findings/SPEC-FINDINGS.md`, both `open`:

- **SF-107** (register `f80fa9c`) – how a requester finds out whether a `Data` DataSet is writable.
  - B1.1.3/B1.1.4 (informative) say "Check `SubscriptionList` and/or `PublicationList`", but no normative text defines how either list shows writability:
    - the PublicationList `Config` describes the publication settings;
    - the SubscriptionList lists "actual subscriptions", with examples of foreign topics.
  - **Proposed interpretation:** a component lists its own `Set` subscription of every writable `Data`/`Config` DataSet as a SubscriptionList entry (`TopicPath` `Oi4v2/<ServiceType>/<AppId>/Set/Data/<Source>/<Tag>`, `Config` `NONE_0`). Other own request subscriptions are not listed. Text proposal for MG 9.1.9 and B1.1.3/B1.1.4 in the register.
  - SDK consequence: entries come with the SubscriptionList in increment 8; until then `BadNotWritable` tells the requester.
- **SF-108** (register `a8f5176`) – the `Source` of the Status event that answers a request to an asset the entity neither is nor represents.
  - Read literally (`Pub/Event/<Source>/…` with the Source of the request), the entity publishes under a foreign Source. Subscribers (D7 T7-MON-04, REQ-CMP-006/007) then take that Source for a subordinate asset without MAM/Health, and any participant can make an entity publish under arbitrary Sources.
  - **Proposed interpretation:** such a Status event carries the entity's own Source (`AppId`); the requester correlates through `ReplyTo`. Text proposal for MG 9.1 in the register.
  - Alternative (b): keep the request's Source and exempt such Sources from the asset rules (D7 change).
  - SDK consequence:
    - the SDK follows the literal text for now (A-91);
    - "as proposed" means a small SDK change in the next cycle: the app's own Status ids, the transient ids dropped;
    - D7 is unchanged in that case;
    - REQ-CMP-047/043 notes follow the text (→ draft).

## Risks and open technical points

- **SF-107/SF-108** are open. Nothing in the SDK blocks on them; SF-108 "as proposed" changes A-91.
- **Handler on the runtime task:** a blocking `on_set` handler delays the bus loop (documented). An offloading variant can come with the consumer (8) if needed.
- **Stale overrides:** an override that no longer fits the definition stays stored but is not applied, until a new `Set PublicationList` overwrites it. This is harmless and bounded by the number of DataSets.
- **D7:** T7-MON-09/13 … 17 are still `planned`. A recorded-capture fixture kind for SDK runs remains a P5 topic.
