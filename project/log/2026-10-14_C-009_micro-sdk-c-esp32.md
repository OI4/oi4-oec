# C-009 – Micro SDK in C (ESP32); D8 scope confirmed

- Date: 2026-10-14
- Phase: P3
- Agent: GitHub Copilot CLI (Claude Opus 5.5)
- Guideline baseline: `oi4-oec-documentation` @ `7bead4c` (unchanged)

## Input from product owner

- **Q-016:** Something from the C spectrum makes sense; think of an ESP32 as the reference board.
- **Q-017:** Confirmed: D8 also checks the platform.

## Decisions

- **ADR-0017: micro SDK in C17.**
  - Structure: portable core + platform abstraction layer (PAL) + reference port for ESP-IDF on the ESP32 (`esp-mqtt`, `esp-tls`/mbedTLS, FreeRTOS).
  - Other ESP32 variants are best effort.
  - API style follows the D2 C API (`oec.h`), without shared code.
  - Consistency with the Rust SDK comes from the D1 schemas, the test vectors and D7.
  - Interpretation of "C spectrum": we chose plain C17 rather than C++, as the smallest common denominator for MCU vendor SDKs. The headers stay usable from C++.
- **Q-017:** ADR-0014 scope confirmed: Service Container compliance of app containers **and** testable platform requirements.

## Consequences

- The `no_std` requirement on the Rust `oec-core` is withdrawn (amendments to ADR-0011 and ADR-0016).
- P4b no longer depends on P4. It needs P1/P2 (REQ catalog, schemas, test vectors) and the API sketch from P3.
- Tests without hardware:
  - host unit tests (CMake + Unity) on macOS, Windows and Linux
  - Espressif QEMU (`esp32`) with D7 – to be confirmed in P4b
  - final check on a real board
