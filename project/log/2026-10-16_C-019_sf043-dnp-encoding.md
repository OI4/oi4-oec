# C-019 – SF-043: dnp-encoding only as a hint at the Oi4Identifier

- Date: 2026-10-16
- Phase: P1
- Agent: GitHub Copilot CLI (Claude Opus 5.5)
- Status: in progress
- Guideline baseline at cycle start: `oi4-oec-documentation` @ `d84c642`, branch `feature/spec-findings` (guideline text = `bc5d063`; `d84c642` only changed `findings/SPEC-FINDINGS.md`)

## Intent

PO decision (chat, 2026-10-16) on SF-043 (e), after the C-018 analysis:

- The `Oi4Identifier` is one way to build an Identification Link according to IEC 61406-1. All prohibitions and requirements of IEC 61406-1 apply to it as well.
- The dnp-encoding helps when elements of the `Oi4Identifier` are not IEC 61406-1 conformant. It stays only as a **hint at the `Oi4Identifier`**: the dnp-encoding may be used if elements of the `Oi4Identifier` are not IEC 61406-1 conformant. It is explained in the appendix (MG A3) only.
- **Everywhere else the dnp-encoding is removed.**
- GL-ADR-010 gets the note that the dnp-encoding is no longer needed (request of 2026-10-15, now refined).

The PO asked to be corrected if his memory was wrong. The agent's check of MG 4.1, 4.3, 4.3.1, 4.3.2, A3 and A4 at `bc5d063`:

- (1) The dnp-encoding masks characters that are not permitted in an IEC 61406-1 Identification Link (space, `"`, `%`, `<`, …) and reserved characters with a structural role, e.g. `/` as the element separator, in the `Model`/`ProductCode`/`SerialNumber` values. MG A3 explains this ("does not contain certain special characters, which might be used in product definitions for any brownfield asset"). So the PO's memory is correct.
- (2) The dnp-encoding is **explained** only in MG A3, which is correct. It is, however, **referenced normatively** outside A3:
  - MG 4.3.1: the field type "dnp-encoded string" of `Model`, `ProductCode` and `SerialNumber`, the length note and the structure line `ManufacturerUri/dnp-encoded(Model)/…`;
  - the note in MG 4.1;
  - the glossary MG A4;
  - plus the TOC entries of A3 (`index.md`, `list-of-tables.md`).
- None of the topic chapters mentions it.

The planned area cycle MSG + ACT moves to C-020; later P1 cycles shift by one, as in C-015 and C-017.
