## Cycle cut (agent decision G-3.4 b, A-145)

Increment 10 fits **one** cycle, not split. The Rust API it wraps is complete since C-060 (provider, write side, Config, events, consumer, Action), so the ABI is a translation layer of one kind throughout: handles, strings, JSON values, callbacks, errors. The pieces (crate, generated header, both library forms, the C programs as tests under sanitizers, the gate step) depend on each other and form one review topic – the language boundary. What `oec` needed for it (JSON on/off ramps and a per-app Syslog function, about 300 lines with tests) is small and went first in its own commit (A-146). ROADMAP table updated: C-061 = 10.

### 2. The crate `oec-ffi` (`847790d`)

`oec/sdk/rust/oec-ffi` (`cdylib` + `staticlib` + `rlib`; features forwarded to `oec`), about 2300 lines of Rust:

| Module | Lines | Content |
|---|---|---|
| `abi.rs` | 386 | `oec_status` codes, thread-local last error and last StatusCode, the guard (`catch_unwind`, error mapping, poisoning), the callback guard (`IN_CALLBACK`), string helpers, `oec_abi_version`/`oec_version`/`oec_string_free` |
| `types.rs` | 287 | protocol constants as `int32_t` typedefs + `#define`s (`oec_level`, `oec_service_type` with `OEC_ST_ANY`, `oec_health`, `oec_resource`, `oec_writable`, `oec_syslog_level`, StatusCodes) and their checked conversion |
| `app.rs` | 725 | product, builder (container storage or explicit broker, credentials, client certificate, string setters), app (`run`/`start`/`shutdown`/`free`, `this`, `add_asset`), `oec_app_syslog` |
| `asset.rs` | 459 | asset remove/health/emit_event/add_data, DataSet update/on_set/remove (fields as JSON with `Precision`), Config add/on_set/get/set |
| `consumer.rs` | 399 | `oec_subscribe`/`oec_subscription_free`, `oec_get`, `oec_set`, `oec_del`, `oec_new_data_set_writer_id`, the `oec_received` struct |

46 exported functions. The header `include/oec.h` (1060 lines) is generated by cbindgen 0.29.4 from `cbindgen.toml` (the contract comment with the memory, string, JSON, callback, thread and panic rules is its `header`; the rustdoc of each function with its `# Safety` section becomes the function comment). `examples/hello.c` and `examples/logger.c` are adapted to the generated header (the logger prints the Generic events and Health of every application – the shape of the logger demo, P6).

Deviations from the P3 contract (all in ADR-0021 amendment C-061, A-147 … A-151): constants instead of C enums; `service_type` in `oec_subscribe`/`oec_get` (and the new requests) with `OEC_ST_ANY` for subscriptions; `level` in `oec_asset_emit_event`; `oec_dataset_set_precision` removed (Precision in `fields_json`); `oec_last_error` set only on failure; `OEC_ERR_NOT_CONNECTED`/`OEC_ERR_STATUS` + `oec_last_status_code`; blocking calls, `run` and `free` refused inside callbacks; child handles valid until the app is freed; `oec_app_start` errors not reported. Additions: `oec_set`, `oec_del`, `oec_new_data_set_writer_id`, `oec_dataset_remove`, `oec_config_set`, `oec_builder_free`, `oec_last_status_code`, three StatusCode constants.

Exit criterion 1 checked item by item against the contract of C-060 (`git show fb857cb:oec/sdk/rust/oec-ffi/include/oec.h`): every type, constant and function exists with the same name, except `oec_dataset_set_precision` (replaced, 5. of the amendment); the `oec_received` struct is unchanged.

### 3. Tests (`a6d633c`, `170a517`)

- Unit tests of the FFI layer (8, no network): errors and panics reported (incl. poisoning), callbacks refuse blocking calls, strings, field JSON, `on_set` verdicts by severity, constants equal to the Rust enums, Targets, answer conversion.
- `tests/c.rs` (3 tests, Unix only): compiles `hello.c`, `logger.c` and the ABI test program `tests/c/abi.c` (494 lines) as C17 with `-Wall -Wextra -Wpedantic -Werror`, each against the shared library and against the static library with `-fsanitize=address,undefined -fno-sanitize-recover=all`, and runs them against the in-process TLS test broker of `oec/tests/testbroker` (`#[path]` module): `hello` – Birth, Health, Close on SIGTERM, exit 0; `logger` – prints the Generic event and the Health of a Rust peer application on the routing broker; `abi` – argument and state errors of every function (NULL, bad UTF-8, out-of-range constants, calls after remove), a provider and a consumer application in one process (`Get`/`Set`/`Del`, Config, `Set Data` with handler verdicts, the Action, `oec_subscription_free` inside its own callback, blocking calls refused in callbacks), and a **stress phase of 6 threads × 150 rounds** against the running provider and consumer (`oec_dataset_update`, `oec_config_get`, `oec_app_syslog`, a `Get` every 25 rounds, and a failing update per round whose last error must stay on its own thread).
- Sanitizers: required by `oec/sdk/check.sh` (`OEC_FFI_REQUIRE_SANITIZERS=1`); on Linux LeakSanitizer as well (`detect_leaks=1`; Apple's arm64 ASan has none). Sanity checks: a deliberate double free in C was reported by ASan (macOS), a deliberately leaked `oec_product` by LSan (Linux).
- `#![cfg(unix)]`: the harness uses `cc`, `kill` and pthreads; the C tests on Windows/MSVC come with the CI of P9.

### 4. Gate (`a259838`)

`oec/sdk/check.sh`: cbindgen must be installed in version 0.29.4 (pinned); the header is regenerated into a temporary file and diffed against the committed one; the C17 syntax check covers the header, `examples/*.c` and `tests/c/*.c`; `cargo clippy` for `crypto-ring` includes `oec-ffi`; the C tests run in `cargo test` for both feature sets. `oec/check.sh` unchanged in its order. READMEs: `oec/sdk/rust/README.md` (crate row, rules, check, how to regenerate the header), `oec/README.md`.

## Risks and open technical points

- `oec_app_start`: an error of the SDK thread (e.g. bootstrap at the first connect) is not reported; the app stays offline and requests fail with `OEC_ERR_NOT_CONNECTED`. A later additive `oec_app_wait`/status function can report it. The logger demo uses `oec_app_run`, which reports it.
- Platform matrix: Windows MSVC (the C tests are Unix only), native amd64 and Windows runs are not verified (exit criterion 5, CI in P9).
- The C ABI is a subset of the Rust API (A-151); P6 needs none of the missing items, the weather demo is in Rust.
- C callers can still break memory rules the ABI cannot check (a freed handle, a non-NUL-terminated string); the header documents them, the sanitizers catch them in the C tests.
