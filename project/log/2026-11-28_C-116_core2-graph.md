## Done

- **New screen of the Core2 display (320 × 240):**
  - header with the title, the connection dot and, with `Cycle` > 0 and more than one sensor, a thin line showing the time to the next sensor;
  - the Label in the largest font that fits (12 pt, 9 pt, then shortened with "..."); a Health chip with the Health in plain words (`NORMAL_0` → "Normal") and the HealthScore;
  - a graph card on the left: the temperature of the last `History` minutes, the curve in the colour of the scale, the area below it fading into the card, dotted lines and labels at the highest and lowest value, the time shown; the latest point flashes white and sends out a fading ring (1.2 s) when a new value arrives;
  - on the right the temperature with a trend arrow (five minutes, ±0.3 °C) and below it the colour scale only as wide as the number, with a knob at the temperature and the scale ends;
  - tiles with the Humidity and the dew point (Magnus formula);
  - footer with the SerialNumber, the age of the last value and one dot per sensor.
- **Paging:** button A, a tap or a swipe to the left shows the next sensor, a swipe to the right the previous one. The PO's report "cannot page" was with a single sensor (the S3), where there is nothing to page and no dots are drawn; with a simulated second sensor (`mosquitto_pub` of a `Climate` publication) the PO confirmed swipe, tap and the flashing point.
- **History:** per sensor a ring of 128 points in RAM (one point per `History`/120 seconds, a newer value within the step replaces it); the curve is clipped at the left edge of the window by interpolation (`drawWideLine` ignores the clip rectangle). New Config object `History` (minutes, 5 … 720, default 30) in `Display`/`General`, kept in NVS as the other values.
- The waiting screen shows the Identification Link one segment per line (it overflowed the screen before).
- README of the Core2 demo, the Community page "Smart sensor on an ESP32" (guideline repository `f4787ec`) and the CHANGELOG updated.

## Agent decisions (G-3.4 b)

- **A-679 Core2 screen:** graph left, temperature, trend and the scale (as wide as the number) right, Humidity and dew point as tiles; the dew point and the trend are derived on the display from `Temperature` and `Humidity`, no new data from the sensor. Not chosen: a full-width graph (the temperature would lose its size) or more sensor values (the DHT22 demo publishes only these two).
- **A-680 History in RAM, set over Config:** 128 points per sensor (six sensors ≈ 6 KB), not persisted – a graph that starts empty after a restart is honest and saves NVS writes every few seconds; `History` 5 … 720 min sets the time per point (span/120).
- **A-681 Health in plain words:** the display strips the `_<number>` suffix of the enumeration value and writes the rest in words with a capital first letter (`NORMAL_0` → "Normal", `MAINTENANCE_REQUIRED_4` → "Maintenance required"), so new values need no table; the colour still comes from the value.
- **A-682 Paging and the pulse:** swipe left/right = next/previous (as on a phone), tap and button A = next; page dots only with more than one sensor. The pulse redraws at about 25 frames per second for 1.2 s after a new value (the device loop waits at most 10 ms meanwhile), otherwise once per second.
