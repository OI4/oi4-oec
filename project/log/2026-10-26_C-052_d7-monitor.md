## Work

### 1. `internal/capture` (`ce712b1`)

Capture format v1 (DESIGN.md §3.2 "As built"):
- line 1 is a header with tool, version, schema bundle, baseline, broker, `insecure`, subscription, `subscribe_qos`, `max_packet_size`, `started`, `note`;
- then one record per message: `{"topic", "payload" | "payload_base64", "size", "received", "qos", "retain"}`;
- an optional trailer `{"ended", "messages", "error"}` is the last line.

Format rules:
- `payload` is the received JSON, compacted. A payload that is not valid JSON is kept byte-exact in `payload_base64`.
- `size` is written only when the received size differs from the compacted length, so REQ-PAG-005 is judged on the bytes as received.
- The reader is strict: unknown keys, a wrong format/version, a time going backwards, or a record after the trailer are errors.
- The writer raises a time that goes backwards to the previous time, so a capture is always replayable.
- `IsCapture` lets `validate` treat a capture as a message file. Messages are named `file:line`.

### 2. `internal/mqttwire` (`4166d79`)

- **Library:** `eclipse/paho.mqtt.golang` **v1.5.1** under EDL-1.0 (ADR-0025 §7).
  - Indirect dependencies: `golang.org/x/net` v0.61.0, `golang.org/x/sync` v0.24.0, `gorilla/websocket` v1.5.3, all BSD-3-Clause.
  - Pinned in `go.mod`/`go.sum`; toolchain `go1.27.3`.
  - `govulncheck ./...` (built with go1.27.3) finds no vulnerabilities. With the old toolchain and x/net v0.44.0 it reported GO-2026-6809 (crypto/x509, fixed in go1.27.3) and x/net advisories in code we do not call; both upgrades remove them.
  - paho's own `packets` codec is also used by the test broker.
- **Client** (`client.go`):
  - `Dial`, `Subscribe`, `Publish`, `Lost`, `Close`, `Kill`.
  - Accepts only `mqtts://` (also `ssl://`, `tls://`). TLS 1.2 minimum, 1.3 maximum.
  - CA from a PEM file, else the system roots.
  - Credentials and/or a client certificate.
  - MQTT 3.1.1, clean session, keep alive 60 s (REQ-MQTT-014), no auto-reconnect.
  - An optional Will (used by tests).
  - `Kill()` closes the TCP connection without DISCONNECT, so the broker publishes the Will.
  - `--insecure` sets `InsecureSkipVerify` only. The CLI warns on stderr and records it.
- **Encrypted keys** (`pkcs8.go`):
  - PKCS#8 PBES2 with PBKDF2 (HMAC-SHA1/-256/-384/-512) and AES-128/192/256-CBC: the format of the dev PKI, of `openssl pkcs8 -topk8 -v2 aes-256-cbc` and of the RIG secret storage.
  - Other schemes are refused with a clear error. No new dependency.
- **Container storage** (`storage.go`, `ReadStorage(root)`) reads:
  - `etc/oi4/mqtt/broker.json`: Address, SecurePort, MaxPacketSize;
  - the CA from `etc/oi4/mqtt/broker_ca.pem` or `etc/oi4/certs/ca.pem`;
  - the client certificate `etc/oi4/certs/<etc/hostname>.pem` with `run/secrets/oi4/private_key.pem` and the base64 `passphrase`;
  - the base64 `credentials`.

  This is the layout of ADR-0026 amendment C-048, with the sample roots of `oec/dev`.
- **Test broker `mqtttest`:** an in-process TLS broker on the paho `packets` codec, plus a throw-away PKI (CA, other CA, client certificate, plain and encrypted key).
  - Supports CONNECT with credentials or a required client certificate, SUBSCRIBE (granted QoS ≤ 1), PUBLISH QoS 0/1 routed with min(QoS), PUBACK, PING, DISCONNECT, and the Will on a lost connection.
  - Test helpers: `DropAll` and `Subscribers(filter)`.
  - No retained messages, no QoS 2. It replaces the "mochi spike" of DESIGN.md §4 (A-53).
- **Tests:** password, client certificate (plain and encrypted key), wrong CA, wrong password, Will, lost connection, storage reader. All on loopback, no outside network.

### 3. `internal/verdict` (`752fdc3`)

The verdict model of DESIGN.md §5:
- **Severity** comes from `levels.L<n>` of the REQ at `--level`: MUST/MUST NOT → fail, SHOULD/SHOULD NOT → warn, MAY → info, no obligation → not judged. Ungraded REQs use their keyword.
- **Observation kinds:** check (pass), violation, hint (info), skip not-applicable, and skip inconclusive.
- **Test outcome:** the worst of its REQs. A not-applicable skip does not make a test worse than pass. A test is `skip` only if all its REQs are (A-56).
- **Exit code:** 1 on any fail; else 4 if an inconclusive skip of a REQ that is a MUST at the level; else 0. `--allow-skip` maps 4 → 0.

### 5. `oec-check monitor`, report (`4c0c062`)

- **Command** (`cmd/oec-check/monitor.go`): flags as in DESIGN.md §3.2/§8 "As built". `--replay` is offline and deterministic. A live run subscribes `Oi4v2/#` with QoS 1 and ends at `--duration`, on SIGINT/SIGTERM, or on a lost connection (`--record` writes the capture as it goes).

- **Tests** (`monitor_test.go`): usage errors, replay of every fixture with the expected exit code, all three formats and `--report`, config file, `--app`, `--allow-skip`.

## Risks and open technical points

- **Monitor scope:** 6 of the 19 monitor tests are still `planned` (A-58). A bus-only `monitor` run cannot judge connection-level REQs (proxy mode, P5). A level claim therefore needs `test` + proxy anyway (ADR-0025 Consequences).
- **Heartbeat in live runs:** a run must last at least 125 s. CI runs of `monitor` against the demos need `--duration` ≥ 2m5s. The live test deliberately runs 6 s and expects exit 4.
- **Retained messages and QoS 2:** the D7 client subscribes with QoS 1. A retained message from the broker is recorded with `retain` and judged (REQ-CMP-009). `mqtttest` has no retained messages; this path is covered by fixtures only.
- **Slow consumers:** the live loop buffers 4096 messages. On a busy bus a slow report writer could block paho's router. Not seen on the dev broker; to be measured with the demos (P6).
- **govulncheck** is not part of the offline gate (A-52).
- **Windows:** `live.sh` is POSIX sh. The Go tests and the CLI are portable, but not yet run on Windows (CI with P4/P5 exit).
