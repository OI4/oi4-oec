# Spec findings – guideline v2.0 draft

Ambiguities, contradictions and gaps found in `oi4-oec-documentation/docs/guideline/` (baseline commit `c85ce2a`).
Each finding gets a proposed interpretation; the decided interpretation is recorded here (and in an ADR if it has protocol impact).

Status: `open` → `proposed` → `decided` (by whom) → `reported` (handed to work group)

| ID | Area | Finding | Location | Proposed interpretation | Status |
|----|------|---------|----------|-------------------------|--------|
| SF-001 | Reserved DataSetWriterIds | 9.2.3 defines PaginationRequest = 1, Pagination = 2, Locale = 3. Example B1.1.15 uses PaginationRequest = 2 and Pagination = 1 (Locale example = 3 is consistent). | 9.2.3 vs B1.1.15 | Follow normative text 9.2.3; fix example. | open |
| SF-002 | MAM `ManufacturerUri` | Ch. 4 requires a domain name (no scheme); examples B1.1.15 / B1.1.16 use `"https://groe.mca"`. | 4 vs B1.1.15/16 | Domain only (`groe.mca`); schema enforces hostname pattern. | open |
| SF-003 | Event `DataSetWriterId` | 10.1.9 template uses `DataSetWriterId: 0` although 0–9 are reserved; B1.1.9 reuses the same id (623 / 625) for different event filters. | 9.2.3, 10.1.9, B1.1.9 | Events use normal ids ≥ 10, unique per (Resource, Source, Filter). | open |
| SF-004 | Event `Filter` in payload | B1.1.9 Syslog example has `"Filter": "/Syslog/Notice"` (leading slash), others `"Status/Good"`. | B1.1.9 | No leading slash: `<EventCategory>/<EventLevel>`. | open |
| SF-005 | Filter and `/` | 8.1.7 says a Filter must not contain `+`, `#`, `/`, but Event (`<EventCategory>/<EventLevel>`) and PublicationList/SubscriptionList (`<ResourceType>/<Tag>`) filters are multi-level. Also "URL encoded string might be best practice" conflicts with IL rule "no %" and is not normative. | 8.1, 8.1.7 | `/` allowed only as level separator in those resource-defined multi-level filters; each filter *level* must not contain `+ # /`. Encoding of special characters inside a level: needs WG decision (candidates: percent-encoding, base64url like IL). | open |
| SF-006 | Status event level | `Pub/Event/<Source>/Status/<StatusCode>`: 8.1.7 says classification `Good`/`Uncertain`/`Bad`, examples use `Good`; unclear whether the symbolic name (e.g. `BadEncodingError`) is allowed. | 8.1.7, 10.1.x, B1.1.9 | Level ∈ {`Good`,`Uncertain`,`Bad`} derived from the top bits of `Number`; the detailed code goes into payload `Number`/`SymbolicId`. | open |
| SF-007 | License resources | `License`/`LicenseText`/`RtLicense` chapters are marked `_ToDelete_`, but 8.2.1 still lists `License`/`LicenseText` as mandatory and 11.3 requires the `License` resource. Same for `Interfaces`, `SBoM`, NE107 (`CAT_NE107_2` still in Event category list). | 8.1.5.1, 8.2.1, 11.3, 9.3.9 | `_ToDelete_` items are removed in 2.0: not mandatory, not in schema, not tested (ADR-0005). | decided (PO, C-002) |
| SF-008 | Metadata `Set` topic | Section "Set Metadata" shows publisher topic `.../Get/Metadata/<Source>/<Tag>`. | 10.1.8 | Copy/paste error → `.../Set/Metadata/<Source>/<Tag>`. | open |
| SF-009 | `MaxPacketSize` unit | Described as "size ... in KiB", but minimum given as "262,144 bytes (256 KiB)" and max INT32max. | 6.1.1 | Unit = bytes; minimum 262144. | open |
| SF-010 | Birth / Will topics | Birth/Will/Close say "refers to topic resource MAM/Health" but not the exact topic (with or without `/<Source>`). | 7.3.3–7.3.5 | `Oi4/<ST>/<AppId>/Pub/MAM/<AppId>` and `.../Pub/Health/<AppId>` (Source = own IL). | open |
| SF-011 | `MessageId` examples | Examples still in old forms, e.g. 9.2.2 `"1567062381000-http://company.com/type/order/4711"` (no ServiceType). Parsing `MessageId` is ambiguous since the IL may contain `-`. | 9.2.1, 9.2.2, 9.2.16 | Treat `MessageId` as opaque unique string for consumers; producers follow `<ms>-<PublisherId>` (first `-` splits). | open |
| SF-012 | OPC UA version | All OPC UA references point to v1.04; current OPC UA spec is 1.05.x (JSON encoding in Part 6 was reworked: e.g. compact/verbose encodings). | 9.x | Keep 1.04-compatible field names as specified; record a 1.05 alignment analysis as follow-up for the WG. | open |
| SF-013 | MQTT version | MQTT 3.1.1 mandated (7.1); text states the decision is "still being observed". MQTT 5 features (request/response, correlation data, user properties, message expiry) would simplify Get/Call. | 7.1 | Implement 3.1.1 per guideline; keep transport abstraction so MQTT 5 can be added; raise question to WG. | open |
| SF-014 | `LocalizedText.Locale` | Text: 2 lowercase + 2–3 uppercase letters, example `"en-EN"` (EN is not a region). | 9.2.7 | Validate BCP 47 subset `^[a-z]{2,3}(-[A-Z]{2,3})?$`; fix example. | open |
| SF-015 | PublicationList `Mode` typo | `ON_REQUEST_APPLCATION_SOURCE_14` (missing "I"). | 9.3.11 | Use `ON_REQUEST_APPLICATION_SOURCE_14`. | open |
| SF-016 | Data `DataSetClassId` | Data/Metadata use `"<(meta)data specific GUID>"`; rules for who assigns it and stability across restarts are missing. Note 9.2.2 "DataSetWriterId is not persistent ... power cycle of a DSWID" (truncated sentence). | 9.2.2, 10.1.7 | Publisher-defined, stable per Data set definition; to be specified. | open |
| SF-017 | Common services | FileUpload/FileDownload/FirmwareUpdate/Blink marked "not maturely specified" – no input/output arguments defined. | 9.4.1–9.4.4 | Out of scope for schema beyond the generic `MSG` envelope until specified; NewDataSetWriterId is fully specified. | open |
| SF-018 | `Get` payload `DataSetClassId` | `Get` request examples carry the resource's `DataSetClassId` while `Messages` contain PaginationRequest/Locale DataSets with other structures. | 10.1.x, B1.1.15 | `DataSetClassId` on `Get` = class of the requested resource; inner messages identified by reserved DataSetWriterIds + Filter. | open |
| SF-019 | `HealthScore` / `RevisionCounter` types | Health `HealthScore` Byte 0..100 optional; MAM `RevisionCounter` Int32 – fine, but Birth example has unquoted placeholders; Close message `HealthScore: 0` with `NORMAL_0` semantics unclear for consumers. | 7.3.4, 9.3.2 | Close = `NORMAL_0`/0 means "gracefully offline"; Registry maps it to state "offline (graceful)". | open |
| SF-020 | `Source` on application-level Pub | Topics allow omitting `Source` (`Pub/MAM`), but the payload `Source` is mandatory per DataSetMessage. Consistency rule between topic `Source` and payload `Source` not explicitly stated for all cases. | 8.1.6, 9.2.3 | If topic contains `Source`, every DataSetMessage `Source` must equal the decoded topic `Source`. | open |
| SF-021 | NewDataSetWriterId example | Keys with trailing spaces (`"DataSetClassId "`, `"CorrelationId "`), typo `InputArgmentResults`; `InputArguments`/`OutputArguments` are arrays of named objects (`[{"Resource": …}]`) whereas OPC UA arguments are positional values. | 10.2.5 | Fix keys; define arguments as positional array whose elements are named objects as shown (schema per service). | open |
| SF-022 | Call/Reply addressing | Not stated whose `ServiceType`/`AppId` is used in the `Reply` topic (caller's or replier's) and how a caller subscribes to replies. | 8.1.4, 10.2.x | `Call` → target's ST/AppId; `Reply` → replier's (= same as Call topic, method swapped); caller matches via `CorrelationId`. | open |
