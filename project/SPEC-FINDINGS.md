# Spec findings – guideline v2.0 draft

Ambiguities, contradictions and gaps found in the guideline (`oi4-oec-documentation`).
**Current baseline: `bc5d063` (branch `feature/spec-findings`, 2026-10-15; guideline text unchanged since `cb50c04`)** – Messaging Guideline (MG, `docs/guideline/`) and Runtime & Infrastructure Guideline (RIG, `docs/infrastructure-guideline/`) with GL-ADR-001 … 017. GL-ADR-017 removed MG 7.2 (content moved to MG 1.3 and MG 9.1) and renumbered the topic elements MG 7.1.1 … 7.1.7 to MG 7.1 … 7.7 (7.1.5.1/7.1.5.2 → 7.5.1/7.5.2); chapter numbers of MG 7 in the findings below are historical. The OEC Process Description (`docs/process-description/`) is informative (GL-ADR-015).

**Section numbers:** GL-ADR-015 renumbered MG chapters 7–10 to 6–9 (MQTT 6, Topics 7, Payload 8, Message Bus 9; former chapter 6 moved to the Process Description). Entries SF-001 … SF-034 cite the numbering valid when they were written (before `49b6fe2`); SF-035 and later use the current numbering.

The PO resolves findings directly in the guideline repo; the guideline repo mirrors this register in `oi4-oec-documentation/findings/SPEC-FINDINGS.md`. **SF ids are shared between both registers – the next free id is SF-040.** New findings are added here first (with location, proposed interpretation) and reported to the PO.

Each finding gets a proposed interpretation. The PO decides (ADR-0007); a decision with protocol impact also gets an ADR (ours) or a GL-ADR (guideline).

Status: `open` → `decided` (PO, cycle) → `reported` (handed to the work group) · `resolved` (fixed in the guideline) · `obsolete` (no longer applicable after a GL-ADR)
